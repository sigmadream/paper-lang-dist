# RTT 고정점 거리 가설 검증 실험 계획

기준일: 2026-09-19. 지표와 종료 규칙은 [abs_PLAN.md](abs_PLAN.md)를 따른다. 이 문서는 그 계획을 실제로 실행하기 위한 가설, 데이터, 실행 환경, 코드 변경, 단계, 비용 예측을 정한다.

## 1. 가설과 예측

abs_PLAN.md의 가정은 "패러다임이 다른 언어로 변환하면 거리가 길어진다"이다. 이를 검증 가능한 형태로 나누면 다음과 같다.

| 가설 | 내용 | 검증에 필요한 경로 |
| --- | --- | --- |
| H1 (주 가설) | 출발 언어 C++에서 패러다임이 다른 중간 언어(Haskell, Prolog)를 거치는 경로는 같은 패러다임의 중간 언어(Python, Java)를 거치는 경로보다 $P_{sf}$가 낮고 $\bar{d}_n$이 크다 | C++ -> Python, C++ -> Java (대조), C++ -> Haskell, C++ -> Prolog (처리) |
| H2 (탐색) | 명령형, 함수형, 논리형 세 출발 언어 사이의 6개 방향 경로에서 $P_{sf}$와 $\bar{d}_n$이 경로마다 다르고, 반대 방향이 대칭이 아니다 | C++, Haskell, Prolog 사이 6개 방향 경로 |

H1은 같은 패러다임 대조 경로 없이는 검증할 수 없다. 현재 데이터와 러너는 C++, Haskell, Prolog만 지원하므로 H2를 1단계로 먼저 실행하고, 대조 경로는 2단계로 추가한다(4장). 대조 경로는 중간 언어로만 쓰이므로 Python, Java 기준 코드는 필요 없고 실행 도구만 있으면 된다.

결과 해석 규칙은 미리 정한다.

- H1 지지: 대조 경로의 $P_{sf}$가 처리 경로보다 높고 $\bar{d}_n$이 작으며, 문제 단위 부트스트랩 신뢰구간이 0을 포함하지 않는다. 두 지표 중 하나만 차이가 나면 부분 지지로 보고한다.
- H1 기각: 차이의 방향이 반대이거나 신뢰구간이 0을 포함한다.
- H2는 가설 검정이 아니라 경로별 값과 순위, 방향 비대칭의 크기를 기술한다. 임계값 0.80, 0.85, 0.90에서 순위가 바뀌면 그 사실을 결과의 일부로 보고한다.
- 어떤 결과든 "이 모델, 이 프롬프트, 이 문제 집합에서의 관찰"로 한정하며 언어 자체의 거리로 일반화하지 않는다.

## 3. 실행 환경

### 3.1 모델과 제공자

| 항목 | 값 |
| --- | --- |
| 제공자 | commandcode.ai Provider API |
| 엔드포인트 | https://api.commandcode.ai/provider/v1 (OpenAI 호환 /chat/completions) |
| 모델 ID | z-ai/glm-5.3-flash (GLM-5.3 Flash) |
| 인증 | 환경 변수 CMD_API_KEY를 Bearer 토큰으로 전송 |
| 단가 | 입력 $0.15/M 토큰, 출력 $0.50/M 토큰, 캐시 읽기 $0.03/M 토큰 |
| 플랜 요금 | 월 $15 |
| 상위 모델 (선택) | zai-org/GLM-5.3 (입력 $1.40/M, 출력 $4.40/M). Flash 결과의 품질이 부족할 때만 별도 설계 버전으로 고려 |

GLM-5.3 Flash는 기본으로 추론(reasoning) 모드가 켜져 있고, 추론 토큰은 completion_tokens에 포함되어 출력 단가로 과금된다. 2026-09-19 사전 점검에서 확인한 추론 제어 결과는 다음과 같다.

| 요청 설정 | 실제 번역 프롬프트의 추론 토큰 | 판정 |
| --- | ---: | --- |
| 설정 없음 | 짧은 질문에도 약 800 | 사용하지 않음 |
| `thinking: {type: disabled}` | 1,298, 4,089 이상 | Z.ai 자체 파라미터라 게이트웨이에서 거의 무시됨. max_tokens 4096에서 추론만으로 잘려 코드가 비어 나옴 |
| `reasoning_effort: none` 또는 `minimal` | 해당 없음 | 400 오류. 허용값은 low, medium, high, xhigh, max |
| `reasoning_effort: low` | 평균 8, 최대 56 | 채택. OpenAI Chat Completions 스키마의 표준 파라미터 |

`reasoning_effort: low`에서 무작위 32개 (문제, 경로) 프롬프트를 측정한 결과 출력 토큰은 평균 248, 90백분위 452, 최대 881이었고 32회 모두 정상 종료(stop)했다. 이를 근거로 max_tokens를 16384로 둔다. 관측 최대의 18배 이상이고, 추론이 억제되지 않았을 때 한 번에 4,096을 넘긴 사례도 수용한다. 실제 과금은 생성된 토큰에만 붙으므로 상한을 높여도 기대 비용은 변하지 않는다.

### 3.2 생성 설정과 시도 반복

abs_PLAN.md는 경로와 문제 조합당 $N = 5$회의 독립 시도를 요구한다. 클라우드 모델이라도 temperature 0에 같은 seed를 쓰면 다섯 시도가 거의 같은 응답을 내므로 $P_{sf}$가 0 또는 1로만 나온다. 따라서 다음 중 하나를 본 실행 전에 확정한다.

| 선택지 | 설정 | 장점 | 단점 |
| --- | --- | --- | --- |
| A (권장) | temperature 0.6, top_p 0.95, 시도별 seed = 기본 seed + 시도 번호, $N = 5$ | 시도 간 변동이 생겨 $P_{sf}$가 의미를 가짐 | 온도가 번역 품질에 영향을 줌. 값을 바꾼 재실험은 별도 설계 버전 |
| B | temperature 0, $N = 1$ | 비용이 1/5, 재현성 높음 | $P_{sf}$가 문제 간 비율(1/15 단위)로만 정의됨. abs_PLAN.md 2.5의 시도 반복을 적용할 수 없음 |

이 문서는 A를 기준으로 비용을 계산한다. 어느 쪽이든 max_tokens는 16384, 요청 시간 제한은 600초로 고정한다(3.1의 측정 근거).

## 4. 러너 코드 변경

현재 fps_experiment.py는 $N = 1$, 단일 임계값 즉시 종료, LM Studio 전제로 짜여 있다. abs_PLAN.md를 실행하려면 다음을 바꿔야 한다.

| 순서 | 파일 | 변경 |
| ---: | --- | --- |
| 1 | providers.py | generation 허용 키에 `thinking`, `reasoning_effort` 추가. 응답 usage에 단가를 곱한 누적 비용을 기록하고 설정의 `cost_cap_usd`를 넘으면 캠페인을 중단 |
| 2 | providers.py | 응답 model 문자열 검사를 완전 일치에서 설정값 접두 일치로 완화하거나 `expected_model` 필드로 분리 |
| 3 | fps_state.py | 임계값 집합 {0.80, 0.85, 0.90} 각각의 최초 도달 단계와 FPS 크기를 기록. 성공 종료를 0.90 도달로 바꾸고, 주 결과는 0.85 최초 도달 시점으로 확정 |
| 4 | fps_experiment.py | 시도 반복 $N$ 루프, 시도별 seed, 시도별 폴더. 종료 유형을 abs_PLAN.md의 다섯 가지(성공, 기능 실패, 상한 초과, 예산 소진, 무효)로 매핑 |
| 5 | fps_experiment.py | experiment_version을 fps-text-v2로 올리고 repeats == 1 제약 제거 |
| 6 | fps_reporting.py | 문제별 $P_{sf}$의 동일 가중 평균, 공통 성공 문제 기준 $\bar{d}_n$, 문제 단위 부트스트랩, 임계값별 표 |
| 7 (2단계) | fps_execution.py | EXTENSIONS와 evaluate에 python, java 추가. 시스템 프롬프트에 두 언어의 도구 조건 추가 |

위 7건은 2026-09-19에 구현했다. 구현 결과와 실행 명령은 다음과 같다.

| 항목 | 구현 |
| --- | --- |
| 설정 파일 | fps_v2.yaml (experiment_version: fps-text-v2). routes, thresholds, repeats, llm.pricing, llm.cost_cap_usd, llm.expected_model 키가 추가됨 |
| 상태 기계 | fps_state.py가 임계값별 최초 도달(reached)을 기록하고 가장 큰 임계값 도달 시 collection_complete로 종료. outcomes()가 임계값별 성공, d_n, 종료 유형(success, functional_failure, fps_limit, budget, invalid)을 돌려줌 |
| 러너 | fps_experiment.py가 (문제, 경로, 시도) 단위로 attempt-NN 폴더를 만들고 시도별 seed를 기본 seed + 시도 번호 - 1로 준다. 유사도 측정 불가는 계속 진행하되, 복원 단계가 한 번도 측정되지 않은 채 끝나면 무효로 분류 |
| 비용 | providers.py가 응답 usage에 pricing을 곱해 phase 폴더의 cost_ledger.jsonl에 누적하고, cost_cap_usd에 닿으면 새 호출을 거부(CostCapReached). 저장된 응답 재사용은 과금하지 않음. 캠페인은 상한 도달 시 중단 |
| 모델명 검사 | 응답 model이 expected_model(기본은 model)을 포함하거나 그 반대면 통과 |
| 보고 | fps_reporting.py가 문제별 P_sf의 동일 가중 평균, 합산 P_sf, 성공 시도 d_n 분포, d+(벌점 11), 임계값별 표와 순위 안정성, 공통 문제 대응 비교(문제 단위 부트스트랩, Bonferroni)를 summary.json과 summary.md로 출력 |
| 대조 언어 | fps_execution.py가 python(py_compile 후 실행)과 java(javac 후 Main 실행)를 평가. routes에 cpp-via-python, cpp-via-java를 추가하면 활성화 |
| 검증 게이트 | scripts/validate_fps_corpus.py가 설정 파일을 인자로 받아 기준 코드 45개를 실행하고 validation.json을 씀. 2026-09-19 실행 결과 45개 모두 13케이스 통과 |
| 게이트웨이 호환 | 모든 요청에 User-Agent rttdist/2.0을 붙임(Python 기본값은 Cloudflare 1010으로 403 차단). Cloudflare 520~524를 재시도 대상에 포함 |
| 키 보호 | api_key_env에 변수 이름이 아닌 값이 들어오면 값을 출력하지 않고 실행을 거부 |

```text
python scripts/validate_fps_corpus.py fps_v2.yaml            # 0단계 게이트
rttdist fps --config fps_v2.yaml --phase pilot                # 1단계
rttdist fps --config fps_v2.yaml --phase pilot --action report
rttdist fps --config fps_v2.yaml --phase main                 # main_design.json 승인 후
```

fps_v2.yaml의 llm 블록은 다음과 같다.

```yaml
llm:
  provider: openai_compatible
  endpoint: https://api.commandcode.ai/provider/v1
  model: z-ai/glm-5.3-flash
  expected_model: glm-5.3-flash
  api_key_env: CMD_API_KEY
  generation:
    temperature: 0.6
    top_p: 0.95
    max_tokens: 16384
    seed: 20260919
    reasoning_effort: low
  request_timeout: 600
  retries: 3
  pricing: {input_per_million: 0.15, output_per_million: 0.50, cached_input_per_million: 0.03}
  cost_cap_usd: 30
```

## 6. 비용 예측: GLM-5.3 Flash, 예산 $50

### 6.1 가정

이전 실험(qwen2.5-coder-7b, 90관측)의 실측값은 호출당 입력 515토큰, 출력 167토큰, 시도당 평균 1.7단계(성공 시도는 4.9단계)였다. GLM-5.3 Flash는 더 긴 코드를 쓰고 성공률이 높아 단계가 늘어나며, 0.90까지 수집을 연장하므로 다음과 같이 보수적으로 잡는다.

| 항목 | 가정 | 근거 |
| --- | --- | --- |
| 호출당 입력 토큰 | 1,000 | 실측 515에 긴 생성 코드가 다시 입력으로 들어가는 효과를 반영 |
| 호출당 출력 토큰 (기본) | 500 | reasoning_effort low 실측 평균 248, 90백분위 452의 상한 쪽 |
| 호출당 출력 토큰 (추론 급증) | 3,000 | 추론이 억제되지 않는 경우를 가정한 스트레스 값 |
| 호출당 비용 (기본) | $0.0004 | 1,000 × 0.15/M + 500 × 0.50/M. 실측 평균은 약 $0.0002 |
| 호출당 비용 (추론 급증) | $0.00165 | 1,000 × 0.15/M + 3,000 × 0.50/M |
| 호출당 최대 비용 | $0.0083 | max_tokens 16384가 전부 출력될 때 |
| 시도 수 | 450 (1~2단계), 600 (3단계 포함) | 15문제 × 경로 수 × $N = 5$ |

시도당 평균 단계 수는 결과에 따라 크게 달라지므로 네 가지 시나리오로 계산한다. 단계 4는 이전 실험처럼 초기 실패가 많은 경우, 8은 절반이 성공하여 0.90까지 이어지는 경우, 12는 대부분 성공하되 수렴이 느린 경우, 20은 모든 시도가 예산을 소진하는 최악이다.

### 6.3 판정

예산 $50에서 플랜 요금 $15와 사전 점검·파일럿 약 $1을 빼면 본 실행에 쓸 수 있는 토큰 비용은 약 $34다. Provider 플랜 요금에는 소멸하지 않는 API 크레딧 $15가 포함되므로 실제 여유는 이보다 크다.

- reasoning_effort low 기준으로 8경로 최악 시나리오도 $4.8이다. 6경로 기대 시나리오(8단계)는 $1.4다.
- 추론이 급증해도 8경로 최악 시나리오가 $19.8로 예산 안이다.
- max_tokens를 16384로 올려 호출당 최대 비용은 $0.0083이 되었다. 모든 호출이 상한까지 출력하는 극단에서는 12,000회에 약 $100이 되므로, 4장의 `cost_cap_usd`를 본 실행 30, 파일럿 5로 두어 이 경우를 막는다. 실측 출력 분포에서는 이 극단에 가까워질 근거가 없다.
- 남는 예산은 $N$을 늘리거나(예: $N = 10$이면 8경로 기본 기대 시나리오 $3.8), 상위 모델 GLM-5.3으로 일부 경로를 재실행하는 데 쓸 수 있다. 어느 쪽이든 별도 설계 버전으로 등록한다.

결론: GLM-5.3 Flash로 6경로 본 실행과 대조 경로 2개까지 $50 안에서 여유 있게 가능하다. 파일럿에서 호출당 토큰과 단계 수를 실측해 이 표를 갱신한다.

### 6.4 실행 시간

사전 점검의 호출당 지연은 중앙값 3.7초, 최대 12초였다. 3,600회 호출의 API 시간은 직렬로 약 4~12시간이고, 여기에 Haskell 컴파일과 JPlag 측정 시간이 더해진다. 경로 간 독립이므로 병렬 2~3으로 줄일 수 있으나, 속도 제한이 공개되어 있지 않으므로 파일럿은 병렬 1로 시작해 429 응답 여부를 보고 조정한다.
