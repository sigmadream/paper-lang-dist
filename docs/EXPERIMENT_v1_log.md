# 1차 실험 실행 기록

2026-09-11. docs/PLAN_v1_metrics.md의 SF 정의를 사용한다. SF는 Stabilized and Functional이며, 첫 왕복의 번호는 t=1이다. 후보 시점 tau_c는 최초 인접 정규화 토큰 해시 일치이며, K=10은 후보 탐색에만 적용한다. 확인 왕복은 tau_c+1부터 tau_c+5까지 수행한다.

원본 20문제를 컴파일하고 문제별 fixture 10쌍을 실행했다. 19문제가 통과했고 IPOP_1260은 wrong_answer로 제외한다. 원본이나 fixture를 수정해 통과시키지 않는다. 실행 결과와 파일 해시는 artifacts-lmstudio/corpus_validation.json에 저장한다.

예비 실행 전 문제 선정: IPOP_1436(반복 탐색), IPOP_2110(정렬 및 이분 탐색), IPOP_2217(정렬 및 산술), IPOP_2579(DP), IPOP_5567(그래프 탐색). 기존 계획의 5문제이며 다양한 구현과 반복 탐색 비용을 포함한다. 본 실험에는 원본 검증을 통과한 최대 19문제를 사용하되, 최종 규모와 복구 예산은 예비 실측 후 별도 기록한다.

예비 설정: Qwen2.5-Coder 7B Instruct, Q4_K_M, 로드 컨텍스트 8192, temperature=0, max_tokens=4096, top_p=1, top_k=0, repeat_penalty=1, seed=20260911. 컴파일 및 fixture당 제한 30초. AST 노드 상한 5000, 별도 프로세스 시간 제한 30초, 메모리 상한 512 MiB. 서버가 공개한 실제 로드 설정과 전송 요청을 함께 보존한다.

Windows 도구 설치: 프로젝트 .tools 아래 GCC 15.2.0을 설치했다. 배포 파일 components-20.0.7z SHA256은 561d873b7f95dbb39a34b7ab00050dc6028808310a847721a8aea5e5b0bff1c9이다. Python은 uv 프로젝트 환경 3.14.7, AST 의존성은 tree-sitter 0.26.0, tree-sitter-cpp 0.23.4, apted 1.0.3이며 psutil 7.2.2로 자식 프로세스 메모리를 관찰한다.

구현 구성: SF 실행과 집계는 experiment_v1.py 및 reporting_v1.py에 분리하고, 기존 CLI가 experiment_version이 있는 설정을 새 실행기로 전달한다. 구버전 산출물은 기존 코드가 읽는다. 데이터 보존 규칙과 SF 정의는 계획을 따른다.

## 예비 실행 완료와 본 실험 사전 고정

예비 run `pilot-v1-qwen25-7b-a`는 15개 실험 단위를 모두 완료했다. 번역/실행 벽시계 시간 1100.576초(18분 20.6초), 논리 요청과 실제 API 시도 각 147회, 호출 시간 합 899.696초, 평균 6.120초, 중앙값 6.225초, 최대 9.323초다. 입력 토큰 120947, 출력 토큰 29070이며 API 오류, 재시도, 절단, parse_error는 모두 0건이다. 실행 평가 시간 합은 195.756초이며 성공 단계의 최대 fixture 시간은 0.986초다.

c=5 성공은 C 2/5, Java 4/5, Python 4/5다. 10개 성공의 tau는 모두 2이며 후보에 도달한 사례는 확인 5회를 모두 유지했다. 실패는 wrong_answer 3건, timeout 1건, runtime_error 1건이다. 후보 미도달 실패는 c=0부터 실패로 계산한다. 완료 검증은 15/15, 조건 해시 일치, 원본 산출물의 해시/fixture/요청 필드, c별 단조성과 성공 수/실패 범주 합을 확인했다.

원본 AST 20개는 모두 측정 가능했고 최대 표현 노드 수 374, 최대 처리 벽시계 시간 1.762초, 최대 프로세스 peak working set 35.778 MiB였다. 예비 생성 C++의 이전 코드 대비 71쌍도 모두 측정 가능했고 최대 노드 수 272, 최대 벽시계 시간 0.869초, 최대 메모리 33.477 MiB였다. 현재 노드/시간/메모리 상한을 유지한다. 변형 집합은 식별자 변경 TSED=1, 서로 다른 구조의 문장 순서 교환 TSED=0.9394, 추상화 후 같은 구조인 문장 교환 TSED=1, 연산자 및 리터럴 변경 TSED=0.9697이었다. 서로 다른 변형의 감소량 순위는 성공 기준으로 삼지 않는다.

본 실험 시작 전 결정: 검증 통과 19문제를 모두 유지하여 19 x 3경로 x 3회 = 171개 관측을 수집한다. 예비 실행과 같은 디코딩/실행/AST 수치 설정을 사용한다. 새 실험 버전은 `v1.1-main-a`, 설정은 `lmstudio_v1.yaml`이다. 실행 중 문제를 교체하거나 실패한 경로만 설정을 늘리지 않는다.

자원 사용 방식: LM Studio의 로드 병렬 용량은 4이다. 본 실험은 서로 독립인 run 3개를 동시 실행하고 각 run 안에서는 문제와 경로를 순차 실행한다. 클라이언트 run 병렬도 3, run당 경로 병렬도 1을 execution_schedule과 조건 해시에 포함한다. 이는 예비 실행의 순차 스케줄과 다르므로 예비 결과를 본 실험에 합치지 않는다. 병렬 추론과 실행 부하 역시 이번 실험 조건이며, 반복 간 차이를 순수한 언어 효과나 직렬 디코딩의 변동으로 해석하지 않는다.

예산: 예비 실행과 같은 경로당 소요 시간을 단순 환산하면 171개 관측의 순차 예상은 약 3.49시간이다. 주어진 19문제의 최대 논리 요청은 run당 1710회, 총 5130회이며 재시도 포함 이론적 최대 API 시도는 20520회다. 예비 호출 평균을 적용한 번역 호출만의 순차 상한 시나리오는 약 8.72시간이다. 실제 병렬 소요 시간은 완료 후 별도 보고하며 단순히 3으로 나눈 시간을 보장하지 않는다. 호출당 최초 요청+최대 3회 일시 오류 재시도, 실험 단위 재개/새 attempt 합계 최대 2회, run당 복구 포함 종료 한도 24시간으로 고정한다. 미해결 인프라 오류는 완료로 표시하지 않는다.

예비 실행 이후 본 실험용 구현 점검: 새 attempt 보존/채택, 실패한 복원 C++의 계산 가능한 해시 기록, 미시작/인프라 제외 구분을 보완했다. 변경은 예비 원본 응답에 소급 적용하지 않으며 예비 시작 당시 소스와 본 실험 최종 소스는 각 run의 code_snapshot 및 별도 조건 해시로 구분한다. 전체 테스트 110개가 통과했다.

본 실험 시작 코드 커밋은 `cca87d17112eac0addea78170cfcfc0aff602dc2`이며, 세 run의 조건 해시는 `29e16350e2c777776f7ff61f106ded25f3d8d66401edf169916f885f1cc82349`로 동일하다. 실행 중 번역기·추출기·실행 어댑터·지표 코드를 변경하지 않는다. 보고서 생성기와 원본 산출물 대조 감사는 실행 코드와 구분해 보완할 수 있으며, 현재 보고서의 수치는 완료된 관측에 대한 잠정 집계다. `complete=false`인 summary와 `partial_audit.json`은 전체 실험의 완료 증거가 아니다. 최종 문서 생성은 3개 본 실험 run 전체의 완료와 `completion_audit.json` 통과를 요구한다.
