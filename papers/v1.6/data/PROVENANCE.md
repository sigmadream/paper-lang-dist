# v1.6 기준 구현과 검증 출처

selection.json이 승인한 15문제 목록과 3개 교체 대응을 고정합니다. 재귀 구현군은 IPOP_11729·IPOP_1992·IPOP_9663이며, 분류는 기존 C++ 기준 구현을 대상으로 합니다. 다른 언어의 반복 대신 꼬리 재귀를 사용한 구현 때문에 비교군 분류를 바꾸지 않습니다. IPOP_2609의 기존 C++는 while 반복 유클리드 구현으로 보존합니다.

문제 명세·공개 예시·평가 13쌍·C++ 구현은 problem 아래 자료를 바이트 그대로 복사합니다. 제외한 IPOP_1436·IPOP_2217·LC_0217과 기존 problem 자료도 변경하거나 삭제하지 않습니다. v1.6은 하노이탑을 새로 포함한 판본이므로 이전 고정 코퍼스의 결과를 하노이탑 결과로 해석하지 않습니다.

## 추가 구현

- references 아래 Python·Java·Haskell·Prolog 각 15개 파일
- Python·Java 전체 30개와 신규 4문제(IPOP_11729·IPOP_2110·IPOP_1992·IPOP_9663)의 Haskell·Prolog 8개는 이번 작업에서 로컬 작성
- 나머지 11문제의 Haskell·Prolog 22개는 scripts/prepare_fps_corpus.py의 HS·PL 구현을 재사용
- N-Queen의 추가 구현은 비트마스크 재귀 탐색과 첫 행 좌우 반사 대칭을 사용하고, C++ 원본의 가변 열·대각선 배열 및 되추적은 그대로 보존
- 외부 모델 API 호출 없음

생성 코퍼스의 manifest.json은 파일별 sha256·언어별 출처·입력 쌍 수를 기록합니다. prepare_v16_corpus.py는 공개 예시와 평가 입력의 공백 정규화 중복, 13개 평가 사이 중복, 누락 입력·정답·기준 구현을 거부합니다. 기존 동결 코퍼스의 내용이 바뀌면 덮어쓰지 않고 별도 경로에서 다시 준비하도록 요구합니다.

## 독립 계산

검증 스크립트는 기준 구현을 호출하지 않는 기존 자료 생성기의 이중 계산을 195개 평가 입력에서 다시 실행합니다. 계산기 자체의 sha256과 사례별 계산 결과·정답 해시·소요 시간을 validation.json의 independent_checks에 보존합니다.

- problem/metadata/ipop19/tools/oracles.py: 소수의 체와 시험 나눗셈, 공유기의 배치 조합·격자 상한, 계단 이동 상태 탐색, 최대공약수의 약수·공배수 순회 등
- problem/metadata/leetcode21/tools/oracles.py: 부분배열 누적합, 경로 수 이항계수, 문자 정렬, 배열 필터, 비트의 반복 나눗셈 등
- 하노이탑: 이동 순서 생성에 더하여 모든 이동의 합법성, 최종 탑 상태, 최소 이동 수 2^n-1 확인
- 쿼드트리: 하향 재귀 분할과 픽셀에서 시작하는 상향 사분면 병합을 대조하여 좌상·우상·좌하·우하 순서 확인
- N-Queen: 비트마스크 탐색을 다시 수행하고 n<=11의 별도 집합 탐색과 대조; n=12..14는 기존 계산기에 기록된 OEIS A000170 계수와 대조

975개 실행 평가는 각 언어 15개 기준 구현을 공통 fps_execution.evaluate로 실행한 결과입니다. 195개 독립 계산은 975개 언어별 실행 수에 합산하지 않습니다. 각 사례 5초·컴파일 180초를 동일하게 적용하고, 누락 도구나 실패 구현은 성공으로 처리하지 않습니다. 검증 결과는 동결 코퍼스 바깥 artifacts-rtt-v1.6/validation에 보존합니다.
