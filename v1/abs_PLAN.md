# RTT와 고정점을 활용한 언어 거리 측정 계획

> 이 문서는 C, Haskell, Prolog의 공통 샘플을 이용하여 언어별 거리를 측정하기 위한 실험이다. 특히, C, Haskell, Prolog의 언어의 특색이 다르기 때문에 언어의 패러다임이 다른 언어 변환의 경우 거리가 길어진다는 것을 가정으로 해당 가정을 검증하기 위한 논문이다.

## 1. 목적과 범위

C, Haskell, Prolog를 각각 출발 언어로 삼아 왕복 번역(Round-Trip Translation, RTT)을 반복하고, 고정점 도달 성공률 $P_{sf}$와 수렴 거리 $d_n$을 측정한다. 코드 유사도 $Sym$은 반복을 멈추는 정지 기준으로만 쓴다. 명령형, 함수형, 논리형 표현을 사용하는 코드가 정지 기준에 도달하기까지 거치는 상태 수와 도달률이 어떻게 달라지는지 비교한다.

이 실험이 측정하는 것은 특정 모델, 프롬프트, 출발 코드, 생성 설정 아래에서 관찰한 번역 경로의 성질이다. 언어 자체의 거리를 직접 측정한다고 주장하지 않으며, 반대 방향 경로에서 같은 값이 나온다고 가정하지도 않는다. 패러다임 차이에 따른 경향은 이 언어 조합과 이 모델에서 관찰한 결과로 해석하고, 언어별 모델 성능과 분리된 효과라고 단정하지 않는다.

| 항목 | 요구사항 또는 설계안 |
| --- | --- |
| 출발 언어 | C, Haskell, Prolog를 모두 포함 |
| 비교 경로 | C -> Python, C -> Java, C -> Haskell, C -> Prolog, Haskell -> Prolog, Prolog -> Haskell |
| 샘플 | 세 언어로 모두 구현 및 검증 가능한 공통 문제 15개 |
| 주 지표 | $P_{sf}$, $d_n$ 두 지표를 독립적으로 보고한다. 실패 벌점 포함 점수 $d^{+}$는 선택적 보조 점수다 |
| 정지 기준 | 인접한 두 복원 코드의 유사도 $Sym$이 주 임계값 $\theta$ 이상이면 근사 고정점 도달로 판정 |
| 거리 상한 | FPS 크기가 10을 초과하면 추가 번역 중지 |

## 2. 측정 계약

### 2.1 표기와 제어 값

원본 코드를 $x_0$, t번째 중간 코드를 $y_t$, 출발 언어로 복원된 코드를 $x_t$로 정의한다. 왕복 1회는 편도 번역 2단계다.

$$
x_0(A) \rightarrow y_1(B) \rightarrow x_1(A) \rightarrow y_2(B) \rightarrow x_2(A) \rightarrow \cdots
$$

실험을 제어하는 값은 다음 다섯 개뿐이다. 모두 초안이며 본 실행 전에 확정하고, 실행 중에는 바꾸지 않는다.

| 제어 값 | 초안 | 의미 |
| --- | ---: | --- |
| 주 임계값 $\theta$ | 0.85 | 주 결과의 근사 고정점 판정 기준. 반올림 전 점수에 적용하고, 같으면 도달로 본다. |
| 민감도 임계값 집합 | {0.80, 0.85, 0.90} | 임계값별 결과를 비교하기 위한 집합. 가장 큰 값 0.90이 수집 종료 임계값이다. |
| FPS 상한 | 10 | FPS 크기가 이를 초과하면 추가 번역을 중지한다. |
| 편도 번역 예산 | 20 | 시도당 편도 번역 횟수 제한. FPS가 늘지 않는 진동을 끊기 위한 것이며 FPS 상한과 다른 개념이다. |
| 시도 횟수 $N$ | 5 | 경로와 문제 조합당 시도 횟수. 실험마다 달리 정할 수 있으며, 앞선 시도의 결과와 무관하게 항상 $N$회를 채운다. |

### 2.2 거리: FPS 크기

FPS는 출발 코드부터 번역 중 생성된 서로 다른 코드 상태를 모은 집합이고, FPS 크기는 그 원소 수다. 코드 상태는 (언어, 소스 해시) 쌍으로 식별하므로 출발 코드만 있을 때 크기는 1이며, 매 편도 번역 후 새 상태가 나올 때만 1씩 늘어난다. 서로 다른 언어의 소스 문자열이 우연히 같더라도 별개 상태다.

소스 해시는 추출된 코드의 줄바꿈만 LF로 통일한 UTF-8 원문에서 계산한다. 식별자, 주석, 공백, Haskell 들여쓰기, Prolog 항을 임의로 제거하지 않는다. 코드 추출에 성공했다면 기능 검사에 실패한 코드도 상태로 세고, 코드를 추출하지 못한 응답은 세지 않는다. 동일 상태의 재등장, API 재시도, 저장된 응답의 재사용은 새 상태를 만들지 않는다. $\theta$는 정지 기준이지 상태 중복 제거 기준이 아니므로, 비슷하지만 다른 코드는 별개 상태로 센다.

| 경로 예시 | FPS 크기 | 완료 왕복 수 |
| --- | ---: | ---: |
| $A_0 \to B_0 \to A_0$ | 2 | 1 |
| $A_0 \to B_0 \to A_1$에서 $\theta$ 도달 | 3 | 1 |
| $A_0 \to B_0 \to A_1 \to B_0 \to A_1$에서 두 번째 복원 시 $\theta$ 도달 | 3 | 2 |

FPS 크기의 의미는 "정지 기준에 도달하기까지 거친 서로 다른 코드 상태의 수"로 제한한다. 값이 작다는 것은 더 적은 상태를 거쳐 정지 기준에 도달했다는 뜻이지, 그 자체로 두 언어가 가깝다는 뜻은 아니다. 모든 단계에서 새 코드가 나오면 왕복 $t$회 종료 시 FPS 크기는 $2t+1$이 되어 왕복 수와 거의 같은 정보를 준다. 상태 재등장이 얼마나 있었는지를 함께 보고해야 FPS 크기가 왕복 수와 다른 정보를 주는지 알 수 있다.

완료 왕복 수와 편도 번역 수는 실행량으로 따로 기록하며 FPS 크기로 환산하지 않는다. 이 계획은 참고 논문의 FPS 크기라는 거리 단위를 채택하되 코드 상태 동일성과 유사도 임계값에 따른 종료를 새로 명시한 코드 실험이므로, 참고 논문의 자연어 프로토콜과 같다고 주장하지 않는다.

### 2.3 정지 기준: 유사도 Sym

$Sym(a, b)$는 출발 언어 코드 $a$, $b$의 JPlag text 모드 `averageSimilarity` 점수이며 0~1 범위다. 세 출발 언어 모두 같은 분석기를 쓰고, JAR 버전, 최소 매칭 토큰 수, 전처리, 입출력 래퍼 포함 여부를 동결한다. 언어별 전용 분석기 점수는 사용하지 않는다. 측정 실패나 길이 미달은 NA와 사유로 기록하며 0이나 1을 대입하거나 다른 분석기로 대체하지 않는다.

유사도는 정지 기준으로만 쓴다. 인접한 두 복원 코드의 유사도 $Sym(x_{t-1}, x_t)$가 $\theta$ 이상이면 근사 고정점 도달로 본다. 원본 대비 유사도 $Sym(x_0, x_t)$는 정지 판정에 쓰지 않고 결과 지표로도 보고하지 않으며, 진단용으로만 기록한다.

같은 분석기를 쓴다고 해서 세 언어에 같은 $\theta$를 적용하는 것이 공정하다는 보장은 없다. JPlag는 text 모드를 단순한 방식이며 주의해서 쓰라고 명시한다. 따라서 본 실행 전 사전 점검에서 언어별로 코드 길이, 공통 입출력 래퍼, 변수명·주석·공백 변화, 연산자·분기 변경이 점수를 얼마나 움직이는지 측정하고, 같은 종류의 변화가 세 언어에서 비슷한 점수 변화를 내는지 비교한다. 언어 간 편차가 크면 $\theta$나 전처리를 새 설계 버전으로 확정한 뒤 본 실행에 들어간다. 이 점검은 새 지표를 만들지 않으며 분석기 적합성 확인에만 쓴다.

임계값 민감도 분석은 저장된 기록만으로는 완전하지 않다. 0.86에서 종료한 시도가 0.90에 나중에 도달했을지는 기록에 없고, 이를 0.90 기준 실패로 처리해서도 안 된다. 그래서 2.4의 종료 규칙은 주 임계값 도달 후에도 수집 종료 임계값 0.90에 도달하거나 실패로 끝날 때까지 번역을 이어간다. 각 임계값의 최초 도달 시점을 따로 계산하여 임계값별 $P_{sf}$와 $d_n$을 구하고, 경로 간 순위가 유지되는지 확인한다.

### 2.4 시도의 종료 규칙

한 시도는 $x_0$에서 시작하여 편도 번역을 반복하고, 매 편도 번역 직후 다음 순서로 판정한다.

| 순서 | 조건 | 처리 |
| ---: | --- | --- |
| 1 | 코드 추출 실패, 컴파일 또는 로딩 실패, 실행 오류, 오답, 시간 초과. 중간 코드와 복원 코드 모두에 적용 | 시도 종료: 기능 실패 |
| 2 | 새 상태가 추가되어 FPS 크기가 상한 10을 초과 | 시도 종료: 상한 초과 |
| 3 | 복원 단계이고 $Sym(x_{t-1}, x_t)$가 측정 가능. 민감도 임계값 집합의 각 값에 대해 처음으로 그 값 이상이 되면 도달 시점과 그때의 FPS 크기를 기록 | 0.90에 도달했으면 시도 종료: 수집 완료. 아니면 계속 |
| 4 | 편도 번역 수가 예산 20에 도달 | 시도 종료: 예산 소진 |
| 5 | 위에 해당하지 않으면 계속. 유사도 측정 불가는 사유만 기록하고 계속 | |

도구 부재나 측정 환경 오류처럼 번역 결과와 무관한 원인으로 판정할 수 없는 시도는 무효로 기록한다.

임계값별 결과는 다음과 같이 확정한다. 어떤 임계값에 대해 시도가 끝나기 전에 최초 도달 시점이 기록되어 있으면 그 임계값 기준으로 성공이고, $d_n$은 그 시점의 FPS 크기다. 기록이 없으면 그 임계값 기준으로는 시도의 종료 유형이 결과다. 주 결과는 주 임계값 $\theta$ 기준 결과이며, $\theta$ 도달 시점까지의 기록으로 확정하고 그 이후의 기록은 주 결과를 바꾸지 않는다. 예를 들어 0.85 도달 뒤 기능 실패로 끝난 시도는 0.85 기준 성공, 0.90 기준 기능 실패다. 이후 기록은 민감도 분석에만 쓴다.

규칙에서 따라 나오는 결과는 다음과 같다. 상한 초과는 그 코드의 기능 평가까지 기록한 뒤 종료하며, 중간 언어 단계라도 복원을 위한 추가 호출을 하지 않는다. FPS 크기 10에서는 동일 상태가 다시 나올 수 있으므로 즉시 중지하지 않고, 11이 되면 유사도가 높아도 어떤 임계값 기준으로도 성공으로 인정하지 않는다. 중간 언어 코드의 재등장만으로는 성공을 판정하지 않는다. 성공 판정에 추가 확인 왕복은 요구하지 않는다. 수집 연장은 편도 번역 예산 20 안에서만 이루어지므로 실행량은 그만큼 늘어난다. 여기서 근사 고정점은 $\theta$ 기준의 근사 수렴이지 코드의 완전한 동일성이나 영구 고정점을 뜻하지 않는다.

### 2.5 시도 반복과 성공률 $P_{sf}$

경로와 문제 조합마다 $x_0$에서 시작하는 독립 시도를 $N$회 실행한다. 앞선 시도가 성공해도 $N$회를 채우며, 첫 성공에서 멈추지 않는다. 첫 성공에서 멈추면 $P_{sf}$가 1/k 꼴로 편향되기 때문이다.

$$ P_{sf} = \frac{\text{성공 시도 수}}{\text{유효 시도 수}}, \qquad \text{유효 시도 수} = N - \text{무효 시도 수} $$

기능 실패, 상한 초과, 예산 소진은 모두 분모에 남는 실패이고 무효만 분모에서 뺀다. 유효 시도가 0이면 NA다. 따라서 $P_{sf}$는 기능 오류 없이 예산과 상한 안에서 근사 고정점에 도달한 비율이며, 기능 보존은 성공의 필요조건이지 $P_{sf}$가 기능 통과율은 아니다. 인접 유사도를 한 번 넘으면 성공이므로 $P_{sf}$는 "제한 내 도달률"이지 반복 안정성의 척도가 아니다.

### 2.6 선택적 보조 점수: 실패 벌점 포함 점수 $d^{+}$

$d_n$은 성공 시도에서만 정의되므로 $P_{sf}$가 낮은 경로에서는 적은 표본의 값만 남아 경로 간 비교가 어렵다. 이를 보완하는 보조 점수로 $d^{+}$를 쓸 수 있다. 실패 시도에 벌점 11을 부여하고 유효 시도 전체를 평균한 값이다.

$$ d^{+} = \frac{\sum_{\text{성공}} d_n + 11 \cdot (\text{실패 시도 수})}{\text{유효 시도 수}} = P_{sf}\,\bar{d}_n + (1 - P_{sf}) \cdot 11 $$

여기서 $\bar{d}_n$은 성공 시도의 평균 $d_n$이다. 범위는 2 이상 11 이하이고 작을수록 좋다. 성공이 없으면 11이고, 유효 시도가 0이면 NA다.

11은 관측된 거리가 아니라 연구자가 정한 벌점이다. 첫 번역에서 컴파일에 실패한 시도나 몇 개 상태를 반복하다 예산을 소진한 시도의 수렴 거리가 11 이상이라는 근거는 없다. 벌점 값의 선택이 곧 $P_{sf}$와 $\bar{d}_n$ 사이의 상대적 중요도를 정하므로, $d^{+}$를 제시할 때는 벌점 11을 항상 명시한다. $d^{+}$는 두 주 지표에서 계산되므로 새 정보를 더하지 않으며, 간결함이 우선이면 보고에서 제외해도 된다. $d_n / P_{sf}$처럼 곱하거나 나누는 형태는 $P_{sf} = 0$에서 정의되지 않고 상한이 없어 채택하지 않는다.

## 3. 보고 지표와 집계

### 3.1 시도 단위 정의

| 지표 | 정의 | 범위 | 해석 |
| --- | --- | --- | --- |
| 수렴 거리 $d_n$ | 성공 시도에서 $\theta$에 처음 도달한 시점의 FPS 크기. n은 그 시점의 편도 번역 단계 번호다 | 2 이상 10 이하의 정수 | 작을수록 더 적은 서로 다른 상태를 거쳐 정지 기준에 도달 |
| 고정점 도달 성공률 $P_{sf}$ | 유효 시도 중 성공 시도의 비율 | 0~1 | 클수록 제한 내 도달률이 높음 |
| 실패 벌점 포함 점수 $d^{+}$ (선택) | 실패 시도에 벌점 11을 준 유효 시도 전체의 평균 | 2 이상 11 이하 | 작을수록 좋음. 벌점 11을 명시 |

$d_n$은 성공 시도에서만 계산하고 실패 시도는 NA다. 실패 시도에서 관측한 FPS 크기는 진단용으로 따로 보고하되 성공 시도의 $d_n$과 합산하거나 평균에 섞지 않는다.

### 3.2 경로별 집계

시도의 단위는 (경로, 문제, 시도 번호)이고, 문제가 표본 추출 단위다. 경로별 값은 다음 규칙으로 합친다.

- 문제별 $P_{sf}$는 그 문제의 유효 시도 중 성공 비율이다. 유효 시도가 0이면 NA다.
- 경로별 $P_{sf}$는 NA가 아닌 문제별 $P_{sf}$의 동일 가중 평균이다. 무효 시도가 있으면 전체 유효 시도를 합쳐 계산한 값과 달라지므로, 경로별 성공 건수와 유효 건수의 합계를 함께 제시한다.
- 경로별 $\bar{d}_n$은 그 경로의 모든 성공 시도의 $d_n$ 평균이며, 성공 표본 수와 성공한 문제 수를 함께 제시한다. 성공한 문제 구성이 경로마다 다르므로 경로 간 $\bar{d}_n$ 비교는 공통으로 성공한 문제만 추린 값도 병기한다.
- $N = 5$이고 무효가 없으면 문제별 $P_{sf}$는 0.2 단위다. 세밀한 순위를 주장하지 않고 성공 건수와 유효 건수, 불확실성을 함께 제시한다. 경로 비교의 신뢰구간은 같은 문제의 반복 시도를 하나로 묶는 문제 단위 부트스트랩으로 구한다.

### 3.3 결과표 구성

| 항목 | 보고 내용 |
| --- | --- |
| 주 지표 1 | 경로별 $P_{sf}$, 성공 건수 / 유효 건수, 신뢰구간 |
| 주 지표 2 | 경로별 $\bar{d}_n$, 성공 표본 수, 성공한 문제 수, 공통 성공 문제 기준 값 |
| 진단 정보 | 종료 유형별 건수, 무효 건수, 실패 시도의 FPS 크기, 상태 재등장 건수 |
| 별도 검증 | 임계값 0.80, 0.85, 0.90 각각의 $P_{sf}$, $\bar{d}_n$과 경로 순위 변화 |
| 선택 사항 | $d^{+}$. 벌점 11을 표에 명시 |

두 주 지표는 독립적으로 보고하고 단일 지표로 합치지 않는다. $d_n$은 성공 조건부이므로 항상 $P_{sf}$와 표본 수를 함께 읽어야 한다.
