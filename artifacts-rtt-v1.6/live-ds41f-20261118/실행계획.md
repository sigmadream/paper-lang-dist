# DeepSeek V4.1 Flash 전환 실행 계획

사용자께서 지정하신 기존 설계를 유지하고 모델만 `deepseek/deepseek-v4.1-flash`로 전환합니다. 기존 전용 래퍼 구조를 별도 파일에 재사용하며 검증된 core·공급자·인증 격리 helper는 변경하지 않습니다. 별도 설계 선택이나 실행 승인 질문 없이 작업하고, 기술 독립 검토만 조정자께 요청합니다.

## 범위와 제약

- 새 래퍼: `scripts/run_deepseek_v41_flash_20261118.py`
- 새 설정: `configs/v1.6/{providers,campaigns}/commandcode_deepseek_v41_flash_20261118.yaml`
- 신규 통합 검사: `tests/integration/test_deepseek_flash_runner.py`
- 출력: `artifacts-rtt-v1.6/live-ds41f-20261118`
- 캠페인: `commandcode-ds41-flash-v16-20261118`
- 문제·평가·프롬프트·시드 20261117·홉·확인·임계치·중단 규칙 유지
- `max_tokens=16384`, `reasoning_effort=low` 유지, temperature·top_p·seed 미추가
- GLM 및 두 Pro 실행·불명 요청·예약 보존, 응답·관측 이관 및 합산 금지
- 전체 200.50달러 내 신규 상한 0.23/49.28/48.62달러, 피크 단가 0.30/1.20/0.006 사용
- 단독 작업, git add·commit·체크아웃·작업자 생성 금지

## 구현 및 검증 순서

1. 기존 원자료·소스·설정의 별도 해시 기준과 공식 문서 조회 시점·출처를 보존합니다.
2. 새 모델 요청·응답 일치, 설정·비용·검토 관문에 대한 실패 검사를 먼저 실행합니다.
3. 별도 래퍼와 설정을 작성하고 실제 원장으로 이전 비용·예약과 신규 한도를 교차 검증합니다.
4. 인증 격리·전송 보호·단일 잠금·소스 무결성·unknown 차단·설계 동일성·Windows 경로를 확인합니다.
5. 관련 회귀·black·오프라인 prepare·관문 검사를 실행하고 원출력·종료코드·해시를 저장합니다.
6. 조정자께 검토 파일·새 manifest·보존 기준·검사 근거를 담아 ask를 보내고 턴을 종료합니다.
7. 실제 독립 검토의 현재 소스·보고서·manifest 해시 일치를 확인한 후에만 지정 uv 명령으로 유료 실행합니다.
8. 독립 OK 1회→12슬롯 파일럿→완전성 감사→새 동결→300슬롯→공식 보고·재현을 감독하고 사전 점검·파일럿·동결·75슬롯마다 조정자께 보고합니다.
9. 524·unknown·inflight 발생 시 재전송·초기화·대체·새 캠페인 자동 시작 없이 보존하고 실패로 감사합니다.
10. 한국어 실행보고서·기계검증 JSON에 실제 슬롯·임계치·모델·비용·토큰·전송·보고·재현·비밀 감사·기존 불변 결과를 기록합니다.

## 검토 중점

- 과거 독립 검토 JSON은 새 Flash 검토로 수락하지 않는 관문
- 정확 모델 이외 응답과 자동 대체 차단
- 비용은 기존 전 캠페인과 미해결 예약 포함, 논리·전송은 캠페인별 별도 공개
- 미보고 실효 설정과 실제 청구액은 null 유지
- 파일럿 불완전 또는 불명 요청의 본 실험 진입 차단

본 계획은 작성·검증·실제 실행의 결과를 미리 통과로 표시하지 않습니다. 구현·오프라인 검증 다음에는 실제 독립 검토 대기가 남습니다.
