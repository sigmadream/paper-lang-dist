# FPS 실험 실행 기록

## 범위와 사전 선정

2026-09-18 사용자 지시에 따라 이번 실측은 LM Studio의 Qwen2.5-Coder 7B Instruct 한 모델로 한정한다. 두 번째 모델과 외부 endpoint 실측은 후속 과제다. 공통 provider 인터페이스와 설정 교체 기능은 구현·검사 대상으로 유지한다.

15문제 × 6방향 × 모델 1개 × 전체 반복 1회 = 본 관측 90건이다. 대표 3문제의 예비 관측 18건은 별도 경로에 저장한다. 예비에 쓴 문제 3개를 본 결과에서 제외한 12문제 민감도 분석도 제공한다. 예비 관측 자체를 본 결과와 합산하지 않는다.

선정은 번역 응답을 받기 전에 수치, 문자열, 리스트, 동적 계획, 탐색·관계의 5영역에서 각 3문제로 고정했다. 목록과 제외 사유는 `data/fps-v1/selection.json`에 있다. 기존 `problem/`의 명세·C++·13개 평가 입력을 변경 없이 복사하고 Haskell·Prolog 기준 코드를 독립적으로 작성했다. 정수 범위·입출력 순서·중복의 의미는 각 명세를 따른다. 출력 비교는 양 끝 공백 및 줄 끝 공백만 무시하며, 내부 공백·행 순서는 보존한다. 원래 명세가 금지한 빈 입력은 추가하지 않았다.

기준 구현에서 C++의 루프·배열과 Haskell의 재귀·리스트/배열, Prolog의 재귀 술어·리스트/항은 서로 다른 초기 표현이다. 소수는 C++의 체와 Haskell·Prolog의 나눗셈 판정, 경로 수는 명령형 배열과 함수형 지연 배열·논리형 행 갱신, 중복 검사는 집합과 정렬 후 인접 검사 등 구현 선택도 다르다. 정렬 문제에는 세 언어 모두 내장 정렬을 쓰지 않으며, 이진 탐색은 배열/Prolog 항의 위치 접근을 사용한다. 다른 문제의 표준 정렬·집합 라이브러리는 허용한다. 이 차이를 언어 패러다임만의 효과로 해석하지 않는다.

## 도구와 기준 코드 검증

`scripts/validate_fps_corpus.py` 실행으로 45개 기준 코드 × 13개 평가 입력 = 585개 실행이 모두 성공했다. 로그와 파일 해시는 `artifacts-lmstudio/fps-v1/preflight-authorized/validation.json`에 있다. 최초 샌드박스 실행에서 Haskell 내부 clang 호출이 권한 오류로 실패했으며, 이 환경 오류는 예비·본 모델 관측에 포함하지 않았다. 그 기록은 `preflight/`에 별도 보존했다.

C++는 프로젝트 내 GCC 14.2.0, Haskell은 GHC 9.10.3, Prolog는 SWI-Prolog 10.0.2를 사용한다. JPlag는 저장소의 6.3.0 JAR와 사용자가 설치한 OpenJDK 26.0.2.1을 사용한다. 앞서 준비한 Java 25는 본 실험에서 사용하지 않는다. 컴파일 제한은 90초, 입력당 실행 제한은 30초다. 자세한 도구 출력과 해시는 검증 JSON에 있다.

## 유사도 진단과 판정 동결

`scripts/calibrate_fps_similarity.py`는 세 언어의 최대공약수 기준 코드에서 동일 소스·반복 측정·공백·주석·식별자·연산자·짧은 코드·공통 부분의 영향을 점검했다. 원본 CSV와 JPlag 출력, 진단 집계는 `artifacts-lmstudio/fps-v1/calibration/`에 있다. 동일·반복·공백 점수는 모두 1이었다. 곱셈을 덧셈으로 바꾼 코드도 1이었다. Prolog의 main 이전 공통 부분 점수는 약 0.852였다. 따라서 text 점수는 구문 또는 의미 동등성 검증으로 사용할 수 없고, 입출력 래퍼에도 영향을 받는다. 짧은 `x`는 측정 불가로 처리되며 0으로 대입하지 않는다.

이 한계를 공개한 상태에서 text를 공통 표면 표현의 안정성 척도로 채택한다. 의미 보존 여부는 모든 생성 단계의 별도 기능 검사로 제한하며, 점수만으로 기능 성공을 선언하지 않는다. θ=0.85는 의미 보존을 예측하도록 학습·최적화한 값이 아니라 사전에 정한 근사 안정화의 운영적 경계다. 본 실행에서 변경하지 않는다. 분석기는 text, 최소 매칭 9토큰, averageSimilarity, 정규화·매치 병합·클러스터링 없음, 입출력 래퍼 포함이다. JPlag text의 한계는 [공식 저장소](https://github.com/jplag/JPlag)에도 명시되어 있다.

상태 동일성은 추출 소스의 CRLF/CR만 LF로 바꾼 SHA-256과 언어의 쌍이다. 주석·공백·식별자는 보존한다. FPS는 원본 상태 1개에서 시작하며 새 코드 상태만 추가한다. 유사도는 중복 제거에 사용하지 않는다. 성공은 생성한 모든 단계의 기능 통과, 인접 복원 코드의 Sym_adj ≥ 0.85, FPS ≤ 10을 처음 만족한 복원 단계다. Sym_final은 그 시점의 원본 대비 점수다. FPS=11이면 코드·기능 검사를 보존한 뒤 중지하며, 중간 언어에서 넘으면 복원 호출이 없다. FPS=10에서 즉시 중지하지 않는다. 중복·진동 보호는 별도 편도 20회 제한이다. 추가 확인 5회는 적용하지 않는다.

설정은 `fps_v1.yaml`이다. 관측당 최대 편도 20회이므로 예비 360회, 본 1,800회, 합계 논리 번역 상한은 2,160회다. 기술적 재시도는 일시 HTTP/연결 오류에만 최대 2회 적용한다. 코드 오답·컴파일 실패·빈 응답은 성공할 때까지 재생성하지 않는다. 모델 요청 시간 제한은 300초, 관측 시간 제한은 4시간이다. 모델 응답이 제공하지 않는 적용 디코딩 설정·사용량은 추정값 대신 null로 둔다. 온도 0과 seed를 설정해도 반복 실행의 결정론을 입증한 것은 아니다.

## 재현 명령

```powershell
.venv/Scripts/python.exe -X utf8 scripts/prepare_fps_corpus.py
.venv/Scripts/python.exe -X utf8 scripts/validate_fps_corpus.py
.venv/Scripts/python.exe -X utf8 scripts/calibrate_fps_similarity.py
.venv/Scripts/python.exe -X utf8 scripts/configure_fps.py
.venv/Scripts/rttdist.exe fps --config fps_v1.yaml --phase pilot
```

같은 `fps` 명령은 저장된 응답·평가·점수를 재사용한다. 데이터·설정·프롬프트·실행기 코드 해시가 달라지면 재개를 거부한다. 예비 검토와 `main_design.json` 동결 뒤 `--phase main`으로 본 실행한다. 이미 동결한 데이터는 재준비하지 않는다. 생성 코드와 기능 오류는 원본 그대로 남긴다.

## 해석 원칙

P_sf는 기능과 수렴의 공동 성공률, P_functional은 종료까지 모든 생성 단계가 기능을 통과한 비율이다. 실패의 성공 조건부 거리와 유사도는 NA다. 종료 FPS 크기는 별도로 공개한다. 성공·평가 실패·미평가·미완료를 합쳐 계획 수와 대조한다. 거리와 원본 유사도를 성공 사례에서만 요약하므로 선택 편향을 함께 설명한다. 반대 방향의 출발 코드가 달라 대칭성이 성립한다고 가정하지 않으며 삼각부등식을 증명하지 않는다. 따라서 d_n은 일반적인 수학적 거리함수가 아니라 모델·프롬프트·문제·초기 표현·판정 규칙에 조건부인 상태 수다.

## 완료 결과와 추가 검토

예비는 성공 2/18건, 컴파일 오류 7건, 실행 오류 9건이었다. 본 실험은 성공 9/90건, 컴파일/로딩 오류 28건, 실행 오류 41건, 오답 10건, 시간 초과 2건이며 미평가·미완료는 없다. 성공은 C++→Haskell→C++ 4/15건, Haskell→C++→Haskell 5/15건에서 관측됐고 나머지 네 경로는 0/15건이었다. 성공 FPS 범위는 3~6, 원본 대비 text 유사도는 0인 성공 사례도 있었다. 원본으로의 복원과 인접 표현의 안정화를 구별한다.

예비 응답 32개·출력 5,776토큰, 본 응답 153개·출력 25,566토큰을 보존했다. API 오류 시도와 출력 잘림은 두 단계 모두 0건이다. 재생성·성공을 위한 재시도는 없었다. 각 단계 원응답, 소스 해시, 실행 stdout과 정답, JPlag CSV, FPS 중복 이력, 종료 우선순위를 다시 대조해 완료 감사를 통과했다. 네트워크를 차단한 두 번의 보고서 생성에서 통계 JSON과 관측 CSV가 완전히 일치했다.

본 실행 시작 후 분기 변경 보조 진단을 추가했다. C++·Haskell·Prolog의 점수는 각각 1.000, 0.886, 0.985로 모두 임계값 이상이었다. 이는 text를 의미 동등성으로 해석하지 말아야 한다는 추가 근거다. 이 후속 진단으로 임계값·프롬프트·데이터·모델 관측을 변경하지 않았다. 예비 감사 보고서의 재생성으로 생긴 파일 해시 차이는 `audit_regeneration_note.json`에 설명했고, 본 실행 전 작성한 `main_design.json`은 유지했다.

관련 회귀 검사 192개와 추가 경계 검사(기존 10개+새 경계 1개)를 통과했다. 기존 Scala 전용 5개는 도구 부재로 제외했다. 검사 XML과 단계별 검증 로그는 `artifacts-lmstudio/fps-v1/`에 있다. 최종 Word는 A4·본문 2단·2페이지이며 원본 백업은 `docs/abs/.source-backup/`에 보존했다. PDF는 실제 Microsoft Word 렌더링으로 확인했다.
