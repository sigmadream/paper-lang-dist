# main 통합과 v1.6 원고 준비 계획

## 통합 순서

1. Flash 실행 프로세스 종료와 최종 실행보고서, 종료 코드, 비밀정보 감사, 공식 보고 및 재현 결과를 대조합니다.
2. 원자료와 동결 소스의 인벤토리, 기존 해시 지도, 검토 경로의 참조 폐쇄를 작성합니다. 보존 대상의 원본 바이트와 준비된 Git blob을 비교하고 비밀정보 감사와 단일 파일 크기 검사를 수행합니다.
3. 실험 인증 환경을 로드하지 않고 전체 pytest를 실행해 실제 로그와 종료 코드를 보존합니다. 확인된 자료와 현재 코드 및 설정을 작업 브랜치에 커밋합니다.
4. 원격을 최신화한 뒤 별도 작업 공간의 v1.5 원고 세 파일의 상태와 SHA-256을 확인하고 main을 빠른 전진(ff-only) 방식으로 통합합니다. 원고 상태와 해시를 다시 확인하고 원격 main 커밋을 대조합니다.
5. 통합한 main에서 v1.6을 생성합니다. 기존 실험 보고서는 그대로 보존하고 논문 작성 골격, 장별 준비 지침, 요약 표와 근거 인덱스를 추가합니다. 공식 원본에서 표 수치를 확인하고 원격 v1.6 커밋을 대조합니다.

## 자료 해석

- Flash의 수집 완료와 임계치별 분석 완전성의 구분
- GLM 공식 원관측, HTTP 524 감사 후 집계, 사후 측정 실패 집계의 구분
- 중단된 Pro 캠페인 두 건의 독립적인 수집·비용 기록 보존
- v1.5와 v1.6의 코퍼스·중단 규칙 차이에 따른 직접 합산 제한

## 검증 기록

1. Flash 단일 실행 종료 코드 0과 최종 비밀정보 감사, 유료 실행 프로세스 종료를 확인했습니다. 본 실험 300슬롯 구조 감사와 공식 수치 재현을 통과했습니다. 유사도를 측정할 수 없어 무효로 기록된 세 슬롯은 세 임계치의 분석 완전성 판정에 그대로 반영합니다.
2. 인증 파일을 로드하지 않은 전체 pytest의 실제 종료 코드는 0이며, 557개 통과와 Matplotlib 사용 중단 예정 경고 1,166개를 기록했습니다. 변경 Python 파일 46개의 black 검사도 종료 코드 0입니다.
