## 서론

> 본 연구는 자연어 처리의 고전적 평가 기법인 왕복 번역(round-trip translation, RTT)을 코드에 적용할 경우, 언어 간 거리를 단정적으로 도출하기보다는 정량적으로 탐색·추정할 수 있다는 가설에서 출발한다. 또한 본 연구는 RTT 기반 언어 거리 측정 프레임워크의 가능성을 검토하는 탐색적 연구(exploratory study)이며, 소규모 대표 코퍼스를 통해 지표의 작동 가능성과 한계를 우선 점검하고, 후속 연구에서 확장 코퍼스를 통해 일반화 가능성을 검증하기 위한 기초를 마련하는 데 목적이 있다.

> 모델의 고유한 특성이 언어 간 거리 측정 결과에 미치는 영향을 탐색적으로 비교 분석한다.

## 실험 설계

> 본 실험은 RTT 기반 언어 거리 측정 프레임워크의 작동 가능성을 확인하기 위한 pilot study로 설계하였다. 따라서 이하의 결과는 선정한 5개 문제에서 관찰된 예비적 경향을 보여주는 것으로 해석해야 하며, 보다 일반적인 결론은 확장 코퍼스를 통한 후속 검증이 필요하다.

## 표 2

"단계별 성공률"로 바꾸는 것이 핵심입니다 현재 표 2의 가장 큰 문제는, 서로 다른 실패 원인이 한 칸에 섞여 있다는 점입니다. 또 3.1의 지표 정의와 3.2의 “의미 통과” 설명도 약간 다르게 읽힙니다. 3.1에서는 대상 언어 코드와 왕복 C++ 코드 모두의 테스트 통과처럼 보이는데, 3.2에서는 대상 언어 코드의 정답 산출처럼 설명됩니다. 이 정의는 반드시 하나로 통일해야 합니다. 

(표 2) 모델 및 언어쌍별 RTT 단계 성공률

| 언어쌍         | 모델    | 1차 번역 성공 | 역번역 성공 | 의미 보존 성공 | 고정점 도달 |
| ------------ | ------- | -------: | -----: | -------: | -----: |
| C++ → C      | qwen2.5 |      4/5 |    3/5 |      3/5 |    2/5 |
|              | gpt-5.4 |      5/5 |    5/5 |      5/5 |    5/5 |
| C++ → Java   | qwen2.5 |      5/5 |    4/5 |      4/5 |    3/5 |
|              | gpt-5.4 |      5/5 |    0/5 |      0/5 |    0/5 |
| C++ → Python | qwen2.5 |      3/5 |    3/5 |      3/5 |    3/5 |
|              | gpt-5.4 |      5/5 |    0/5 |      0/5 |    0/5 |

### 표 아래 각주 예시

> 1차 번역 성공은 C++ 원본을 대상 언어 코드로 변환한 뒤 구문 검사 및 실행이 가능한 경우를 의미한다.
> 역번역 성공은 대상 언어 코드를 다시 C++로 변환한 뒤 컴파일 및 실행이 가능한 경우를 의미한다.
> 의미 보존 성공은 원본 C++과 왕복 후 C++이 동일 테스트 세트를 통과한 경우로 정의한다.
> 고정점 도달은 최대 (K)회 RTT 내에 정규화된(normalized) 코드가 더 이상 변하지 않은 경우를 의미한다.

여기서 **(K)값과 정규화 기준**도 3.1에 꼭 써야 합니다. 예를 들면 “공백, 주석, 단순 포매팅 차이는 제거한 뒤 동일성을 판정하였다”처럼요. 참고로, 더 엄밀하게 하려면 의미를 두 단계로 쪼개는 방식도 좋습니다.

* 대상 언어 의미 통과
* 왕복 후 C++ 의미 통과

다만 지면이 2쪽이라면 지금 제안한 4단계 표가 가장 현실적입니다.

## 표 3은 평균만 두지 말고 “도달률 + 분포”로 바꾸십시오

현재처럼 평균 반복 횟수만 두면, **조기 실패가 많은 모델이 오히려 평균이 작아 보여** 언어 거리가 작은 것처럼 읽히는 문제가 생깁니다. 그래서 표 3은 최소한 **고정점 도달률**과 **분포 통계**를 함께 보여줘야 합니다.

(표 3) 언어쌍별 고정점 반복 횟수의 분포

| 언어쌍         | 모델     | 고정점 도달률 | 전체 반복 횟수 median [IQR] | 도달 사례 반복 횟수 mean ± SD |
| ------------ | ------- | ------: | --------------------: | --------------------: |
| C++ → C      | qwen2.5 |     2/5 |              2 [1–4] |            2.0 ± 0.0 |
|              | gpt-5.4 |     5/5 |             3 [2–10] |            5.4 ± 6.0 |
| C++ → Java   | qwen2.5 |     3/5 |              2 [2–4] |            2.3 ± 0.6 |
|              | gpt-5.4 |     0/5 |              1 [1–2] |                   N/A |
| C++ → Python | qwen2.5 |     3/5 |              2 [2–3] |            2.7 ± 0.6 |
|              | gpt-5.4 |     0/5 |              1 [1–1] |                   N/A |

이 표의 핵심은 다음입니다.

* **고정점 도달률**을 먼저 보여준다.
* **전체 반복 횟수**는 median[IQR]로 둔다. 실패 때문에 분포가 치우칠 수 있어서입니다.
* **도달 사례 반복 횟수**는 mean±SD로 따로 둔다.

지면이 더 좁으면, **“고정점 도달률 + 도달 사례 반복 횟수 median[IQR]”**만 남겨도 충분합니다.

### 3.2 본문

> 표 3은 고정점 도달률과 반복 횟수 분포를 함께 제시한다. 조기 실패가 빈번한 언어쌍에서는 전체 평균 반복 횟수가 낮게 나타날 수 있으므로, 이를 곧바로 낮은 언어 거리로 해석해서는 안 된다. 따라서 반복 횟수는 고정점 도달률 및 도달 사례의 분포와 함께 해석하는 것이 적절하다.

## 표 4는 언어쌍 정보가 보이게 바꾸십시오

현재 표 4는 문제별 MOSS만 있고, **어느 언어쌍에서 구조 보존이 어려웠는지**가 보이지 않습니다. 그래서 리뷰어 입장에서는 “몇 문제 평균이네”라는 인상이 강해집니다.

**(표 4) 언어쌍별 MOSS 유사도 분포**

| 언어쌍          | 모델      | MOSS 평균 ± SD | median [IQR] | 최소–최대 |
| ------------ | ------- | -----------: | -----------: | ----: |
| C++ → C      | qwen2.5 | 19.3 ± 22.5 |           14 | 0–44  |
|              | gpt-5.4 | 25.4 ± 24.4 |   31 [0–48]  | 0–52  |
| C++ → Java   | qwen2.5 | 63.8 ± 14.2 |  67 [49–75]  | 44–77 |
|              | gpt-5.4 | 36.7 ± 41.0 |           29 | 0–81  |
| C++ → Python | qwen2.5 |  0.0 ± 0.0  |            0 | 0–0   |
|              | gpt-5.4 | 36.4 ± 23.8 |  34 [16–58]  | 0–61  |

문제 수를 많이 늘릴 수 있다면, 표 대신 **박스플롯**이 더 좋습니다. 하지만 현재처럼 2쪽 지면이면, 표 4를 이 구조로 바꾸는 쪽이 현실적입니다.

### 3.2 본문

> 표 4는 MOSS 유사도를 문제별 단일값이 아니라 언어쌍 단위의 분포로 재구성한 것이다. 이를 통해 특정 언어쌍에서 구조 보존이 일관되게 어려운지, 혹은 일부 문제에만 국한된 현상인지를 구분할 수 있다. 즉, MOSS는 단순 평균값보다 언어쌍별 분포와 편차를 함께 보아야 해석이 가능하다.

## 지금 데이터만으로는 새 표를 완전히 채울 수 없습니다

이건 꼭 말씀드려야 합니다. 새 표 2~4는 **현재 논문에 적힌 집계값만으로는 채워지지 않습니다.** 다시 필요한 것은 다음 로그입니다.

* 문제별 1차 번역 성공 여부
* 문제별 역번역 성공 여부
* 문제별 의미 보존 여부
* 문제별 고정점 도달 여부와 반복 횟수
* 문제별·언어쌍별 MOSS

즉, 실험 로그를 다시 꺼내서 **문제 단위로 재집계**해야 합니다. 리뷰 대응에서도 이 재집계가 가장 중요합니다.

## 리뷰 답변서

> 소중한 지적에 감사드립니다. 지적해 주신 바와 같이 초기 원고는 소규모 코퍼스와 평균 중심 결과 제시로 인해 분석 결과의 일반성이 충분히 드러나지 않는 한계가 있었습니다. 이에 개정본에서는 본 연구의 성격을 RTT 기반 언어 거리 측정 프레임워크의 가능성을 검토하는 탐색적 연구로 명시하였고, 결과 제시 방식도 평균값 중심에서 단계별 성공률과 분포 통계 중심으로 개편하였습니다. 구체적으로, RTT 파이프라인을 1차 번역, 역번역, 의미 보존, 고정점 도달의 단계로 분리하여 제시하고, 반복 횟수 및 MOSS 유사도에 대해서도 분산과 분포 요약을 함께 보고하도록 수정하였습니다. 또한 본문에서 소규모 코퍼스에 따른 일반화의 한계를 명시하고, 확장 코퍼스를 활용한 후속 검증 필요성을 보강하였습니다.

마지막으로, 4장 제목은 **“제언”보다 “논의 및 한계”**로 바꾸는 편이 이번 리뷰 대응과 더 잘 맞습니다.

실험 로그(문제별 단계 성공 여부, 반복 횟수, MOSS)가 있으면 표 2~4를 실제 숫자로 채운 형태와 3.2 완성 문단까지 바로 정리해 드리겠습니다.
