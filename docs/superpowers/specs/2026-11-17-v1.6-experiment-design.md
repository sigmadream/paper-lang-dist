# v1.6 실험 코드 개선 설계

작성일: 2026-11-17

이 문서는 기존 분석과 사용자의 추가 요구를 바탕으로 이번 TODO의 구현 기준을 확정합니다. 코드를 구현하거나 새 실험을 수행했다는 의미는 아닙니다. 사용자가 지정한 조건은 논문의 주장 유지, 문제 수 고정, 재귀 문제 포함, 여러 API 제공자 지원입니다. 아래의 문제 교체 목록과 판정·통계·연결 방식은 이를 충족하기 위해 선택한 설계입니다.

## 연구 주장과 선택한 해결 방식

논문의 핵심은 기능 검사를 통과하는 왕복 번역에서 근사 고정점까지의 평균 편도 번역 횟수와 도달률을 결합하여 언어 경유 경로를 비교한다는 것입니다. v1.6에서는 이 정의와 식 `D = mean_hops / reach_rate`를 유지합니다. D는 모델·코퍼스·프롬프트·평가 조건에 의존하는 조작적 의미 거리 지수로 설명합니다. 언어 자체의 보편적인 거리나 실제 마이그레이션 비용으로 해석하지 않습니다.

| 검토한 방식 | 판단 | 이유 |
|---|---|---|
| 기존 수치를 유지하고 지표를 고유 상태 수로 개명 | 미채택 | 논문의 평균 홉 수 정의와 다른 연구 질문 |
| 실제 도달 홉 수로 계산하고 상태 수를 보조 관측으로 분리 | 채택 | 논문의 식과 측정 대상을 일치시키는 방식 |
| 연속 두 번 임계치 충족을 주 성공 기준으로 변경 | 미채택 | 최초 도달 정의 변경; 추가 안정성 확인은 보조 분석으로 분리 |

결과가 가설과 다르더라도 판정 규칙과 문제 구성을 사후 변경하지 않습니다. 재귀 문제에서 Haskell 경로가 좋아질 것이라고 전제하지 않습니다.

## 홉·성공·중단의 정의

1. `reached_step`은 해당 임계치를 처음 충족한 성공 복원 단계의 편도 번호입니다. 성공한 시도의 값은 2·4·6·8·10 중 하나입니다.
2. `unique_state_count_at_reach`는 원본을 포함한 `(언어, 줄바꿈을 통일한 소스 해시)`의 개수입니다. `d_n`이라는 모호한 이름은 새 스키마에서 사용하지 않습니다.
3. 해당 시점까지 모든 중간·복원 코드가 13개 테스트를 통과하고 인접 복원 유사도가 임계치 이상이면 성공입니다. 각 임계치의 최초 도달 결과는 이후 실패로 변경하지 않습니다.
4. 10번째 홉도 기능 검사와 유사도 판정 후 예산 소진을 결정합니다. 새 상태가 11개여도 성공 판정이 가능합니다.
5. 도달 전 기능 실패는 `functional_failure`, 평가 가능한 상태로 10홉까지 미도달하면 `hop_limit`, 제공자·도구·측정 장애로 판정을 완료할 수 없으면 `invalid`입니다. 각 임계치별로 이 분류를 보관합니다.
6. 복원 단계의 유사도 측정 장애는 해당 입력으로 로컬 재측정 후에도 해결되지 않으면 관찰을 중단합니다. 아직 미도달한 임계치는 `invalid`로 남기며 미도달로 대입하지 않습니다. 이미 도달한 임계치는 유지합니다.
7. 아직 호출하지 않은 계획 슬롯은 `incomplete`로 구분합니다. 무효·누락을 실패로 바꾸거나 성공할 때까지 새 시도로 교체하지 않습니다.

### 추가 안정성 확인과 민감도 수집

주 임계치 도달 직후 다음 1회 왕복의 기능 통과와 인접 유사도 0.85 이상 유지 여부를 `confirmation_status=passed/failed/unavailable`로 기록합니다. 기능 실패나 낮은 유사도는 `failed`, 인프라·측정 장애 또는 실행 예산으로 수행하지 못한 경우는 `unavailable`입니다. 이전 성공 판정과 D를 소급 변경하지 않습니다.

탐색 10홉 안에서는 0.90 최초 도달까지 민감도 자료를 계속 수집합니다. 모든 임계치를 도달하고 주 임계치의 확인까지 끝나면 중단합니다. 주 임계치에 10홉에서 처음 도달했다면 11·12홉은 확인에만 사용하며 새 임계치 도달로 집계하지 않습니다. 0.90에 먼저 도달했더라도 주 임계치의 다음 왕복 확인이 끝나기 전에는 중단하지 않습니다. 10홉 이내의 후속 단계에서 실패하면 미도달 임계치와 확인 상태만 갱신합니다.

10홉의 평가가 끝나면 모든 탐색 결과를 동결합니다. 예를 들어 10홉에서 0.85에 처음 도달하고 0.90에는 미도달한 뒤 11홉에서 오답이 발생하면, 0.85는 성공, 0.90은 hop_limit, 확인은 failed입니다. 확인 전용 단계의 기능·인프라·측정 실패는 동결된 임계치별 결과를 바꾸지 않습니다.

한 번의 추가 확인은 장기 수렴 증명이 아닙니다. 본문의 주 결과는 최초 도달, 보조 결과는 다음 왕복의 안정성 유지로 기술합니다. 호출 수는 탐색·확인·재시도별로, 홉 수는 최초 도달·전체 생성 단계별로 나누어 보고합니다. 한 시도는 최대 12개 논리 번역 요청이며 통신 재시도 횟수는 별도입니다.

재귀 구현군은 위 신규 3문제이고 나머지는 비교군입니다. 유클리드 호제법은 재귀적으로 구현할 수 있지만 현재 C++ 코드는 반복형이므로 재귀군에 포함하지 않습니다. 재귀군을 순수 함수형 문제군이라고 부르지 않습니다. N-Queen 기준 코드에는 가변 상태와 되추적이 함께 존재합니다.

문제 메타데이터에 재귀 여부·종류·가변 상태·되추적·출력 규모를 사전 기록합니다. 생성된 Haskell 코드는 재귀, 누산기, 리스트 처리, 명시적 상태 사용을 근거 코드 위치와 함께 기술적으로 주석 처리합니다. 자동 분석 실패는 미확인으로 남기며 기능 통과와 동일시하지 않습니다. 군별 도달률·홉 수·실패 분포와 Haskell-대조 경로 차이를 제시하되 3문제의 탐색적 분석으로 한정하고 인과 효과나 우월성을 확정하지 않습니다.

각 15문제에 C++·Python·Java·Haskell·Prolog 기준 구현을 준비하여 13개 테스트와 5초 제한을 사전 점검합니다. 기준 구현은 성능·평가 도구 점검용이며 모델에 중간 언어 정답을 제공하지 않습니다. 특히 하노이탑의 대량 출력과 N-Queen의 실행 시간은 유료 실험 전에 검증합니다. 문제가 발견되면 결과를 보기 전에 기준 구현 또는 평가 자료를 수정하고 전체 해시를 다시 동결합니다. 실행 중 문제 교체나 언어별 시간 완화는 하지 않습니다.

## 통계와 논문 해석

| 지표 | 집계 정의 |
|---|---|
| 도달률 P | 유효한 시도 중 해당 임계치 성공 비율; 문제별 분모·비율도 공개 |
| 평균 홉 수 H | 성공 시도의 reached_step 합 / 성공 수 |
| 거리 D | 반올림 전 H / P; 성공 0이면 결측과 사유, 임의 벌점·무한대 대입 없음 |
| 고유 상태 수 | 도달 시점의 보조 분포; D에 미사용 |
| 인접 유사도 | 2홉 첫 복원 시점과 성공 도달 시점의 분포를 별도로 보고 |
| 원본 유사도 | 주 임계치 성공 시점의 원본 대비 값, 성공 시도당 1개 |
| 단계 통과율 | 방향·단계·탐색/확인 구분; 분모와 대상 실행 수 공개 |
| 전체 단계 유사도 | 오래 진행한 시도의 가중 효과를 명시한 보조 기술통계 |

본 실험의 완전성은 임계치별 `complete_by_threshold`로 판정합니다. 해당 임계치에서 각 경로의 유효 시도 75개가 확보된 경우에만 그 임계치의 완전한 비교표와 확증적 비교를 생성합니다. 0.85 도달 이후 장애로 0.90이 무효가 되어도 0.85의 완전성은 유지할 수 있습니다. 300개의 슬롯이 모두 종료되어도 무효가 남으면 자료 수집 종료와 분석용 완전성을 구분합니다. 불완전 실행의 기술통계에는 실제 분모를 사용하고 확증적 경로 비교에서 제외합니다. 기존 코드의 문제별 동일 가중 평균과 합산 도달률이 다른 경우를 숨기지 않습니다.

확인 분석의 대상은 주 임계치 성공 시도 전체입니다. passed·failed·unavailable 건수와 전체 성공 시도 수를 함께 제시하고, 판정 가능한 시도에서의 유지율 `passed / (passed + failed)` 및 미확인 비율 `unavailable / primary_successes`를 분리합니다. 분모가 0이면 결측으로 표시합니다.

15개 문제를 블록으로 10,000회 재표집하며 한 블록에 동일 문제의 경로별 5개 시도를 함께 유지합니다. 매 재표집에서 P·H·D를 다시 계산합니다. 경로별 D를 먼저 문제별로 나누어 평균하는 다른 지표로 바꾸지 않습니다. 비교 대상은 Python–Java, Python–Haskell, Python–Prolog, Java–Haskell, Java–Prolog, Haskell–Prolog의 6쌍입니다. 주 임계치에서 P·H·D의 18개 비교에 Bonferroni 보정 구간을 사용하고, 같은 재표집에서 차이를 계산합니다. 0.80·0.90은 민감도 기술통계와 미보정 구간을 구분 표시하며 추가 확증 주장에 사용하지 않습니다.

`Python < Java < Haskell < Prolog`는 우선 D의 관측 순위로 보고합니다. 전체 순위의 통계적 지지는 주 임계치의 인접 3쌍 D 차이가 위 보정 구간에서 모두 예상 방향으로 0을 제외할 때만 표시합니다. 일부 차이가 불확실하면 부분 순위와 불확실한 쌍을 공개합니다. H 또는 P의 순위가 D와 같아야 한다고 요구하지 않습니다. 여러 모델에 대한 판단은 모델 실행별로 표시하고, 전체 모델을 합친 동시 신뢰수준으로 해석하지 않습니다.

재표집에서 성공 0으로 H 또는 D가 정의되지 않는 경우 그 비율을 공개하고 해당 무조건부 구간과 순위 판정을 산출 불가로 표시합니다. 정의되는 표본만 남겨 정상 구간처럼 보고하지 않습니다. 도달률 구간만으로 D 순위를 확정하지 않습니다. 재귀 하위군은 사전 지정한 탐색적 기술통계로 보고합니다.

기능 검사는 테스트 범위의 보존 근거이며 전체 의미 동등성 증명으로 표현하지 않습니다. JPlag 0은 설정된 매칭 기준에서의 관측값이며 구조나 의미가 완전히 소멸했다는 뜻으로 해석하지 않습니다. 모델 간 동일 순위는 관측한 조건에서의 재현성으로 설명합니다.

### 생성 설정과 응답 계약

공통 비교 프로파일의 요청값은 temperature 0.6, top_p 0.95, 출력 상한 16384, 지원 시 시도별 seed입니다. reasoning 설정은 모델별 공식 의미를 기록하며 서로 다른 API의 `low`를 동일한 추론량으로 취급하지 않습니다. 미지원 옵션을 조용히 삭제하거나 다른 값으로 재호출하지 않습니다. 실행 전에 호환되는 별도 프로파일을 생성·동결하여 사용하고, 같은 조건의 비교 여부를 표시합니다.

공급자 정규화 결과의 필수 키는 `text`, `finish_reason`, `requested_model`, `actual_model`, `model_evidence`, `usage`, `usage_raw`, `cost_usd`, `cost_source`, `request_id`, `requested_generation`, `sent_generation`, `effective_generation`, `raw_response_path`, `protocol`, `provider`입니다. 확인할 수 없는 값은 null과 사유를 저장하며 요청값을 적용값으로 복사하지 않습니다. 모델 검증은 정확 일치 또는 설정에 명시한 별칭 목록만 허용합니다. 응답에 모델 ID가 없으면 검증된 것으로 간주하지 않습니다.

정상 수신된 모델의 빈 출력·잘림·복수 코드 블록은 형식 실패로 기록하며 새 응답을 뽑지 않습니다. 비정상 프로토콜·HTTP·모델 불일치는 기능 실패와 분리합니다. 단일 코드 블록 또는 단일 원문 소스만 허용하는 추출 규칙은 사전 고정합니다. 응답 본문을 먼저 보관한 후 정규화하여 중간 충돌로 재생성이 발생하지 않게 합니다.

## 실행·비용·재현성

논리 번역 단계, 전송 시도, 실제 응답, 과금 단위를 별도 ID와 장부로 추적합니다. 429 등 사전 지정 통신 오류만 최대 2회 재시도하며 응답을 받은 뒤 재생성하지 않습니다. 응답 수신 여부가 불명확한 시간 초과는 과금·생성 여부 불명으로 남기고 멱등성 보장이 없는 자동 재호출을 하지 않습니다. 계획된 시도 번호를 새 번호로 교체하지 않습니다.

비용·호출 수·토큰 예산은 실행 설정에 명시합니다. 단가 미상은 0달러가 아니며 호출 수 상한으로 중단할 수 있습니다. 달러 상한이 필수인 실행은 단가·최대 과금량 추정이 불가능하면 시작하지 않습니다. 알려진 비용의 누적과 진행 중 요청의 예약 비용을 함께 고려하며 샤드 간 장부를 조정합니다. 인증값은 환경 변수 또는 SDK 공식 인증에 두고 산출물에 기록하지 않습니다.

파일럿은 고정 15문제 중 `IPOP_11729`, `IPOP_1992`, `LC_0053`에서 4경로×1회로 수행합니다. 본 실험 300개 시도와 별도 단계·요청 ID·아티팩트로 저장하고 재사용하지 않습니다. 문제 수는 전체 고유 문제 15개로 유지합니다. 파일럿은 연결·성능·산출물 점검이며 결과 순위에 따라 조건을 조정하지 않습니다.

실험 계약에 문제 목록과 파일 해시, 코드·보고기 해시, 프롬프트, 도구 버전, 모델·제공자·프로파일, 예산, 평가·중단·재시도 규칙을 동결합니다. 계약이 다르면 기존 실행 재개를 거부합니다. `papers/v1.5` 원문과 과거 결과는 유지합니다. 원자료를 찾으면 기존 규칙 아래 홉 수를 재집계할 수 있지만 v1.6과 종료 규칙·코퍼스가 다르므로 합산하거나 직접 개선율로 주장하지 않습니다.
