# 원안
1. C++로 간단한 프로그램(예컨대 백준 스타일의 간단한 문제 해법)을 작성
2. C++와 C, C++과 Java, C++과 Python 언어 사이의 거리를 측정
3. 실험 결과 정리

# 계획

> '언어 간 유사성 분석(Cross-Language Similarity Analysis)' 또는 '코드 메트릭을 활용한 언어적 거리 측정' 연구로 발전시키기에 매우 흥미로운 주제

'언어 사이의 거리'를 정의하는 것이 가장 중요합니다. 단순히 코드의 길이가 아니라, 다음 세 가지 관점에서 거리를 측정할 것을 권장합니다.

## A. 구문적 거리 (Syntactic Distance)

- 방법: 각 언어로 작성된 코드의 추상 구문 트리(AST)를 추출합니다.
- 지표: Tree Edit Distance (TED)를 사용하여 C++의 AST와 타 언어 AST 간의 구조적 차이를 수치화합니다.
- 도구: `Clang` (C/C++), `javaparser` (Java), `ast` module (Python).

## B. 복잡도 및 어휘적 거리 (Complexity & Lexical Distance)

- 지표: Halstead Metrics (오퍼레이터/오퍼랜드 수)와 Cyclomatic Complexity를 비교합니다.
- 분석: 같은 알고리즘을 구현했을 때, Python은 얼마나 간결해지는지, C/C++는 얼마나 하위 수준의 제어가 필요한지를 지표로 증명합니다.

## C. 실행 성능 거리 (Performance Distance)

> 본 연구에서는 LLM을 일종의 '언어적 변조기(Modulator)'로 활용한다. C++ 코드가 타 언어를 거쳐 다시 C++로 회귀하는 과정에서 발생하는 구조적 왜곡을 관찰함으로써, 인간의 개입 없이도 두 프로그래밍 언어가 공유하는 추상화의 깊이와 문법적 대응성을 정량화할 수 있다.

기존의 물리적인 실행 속도 대신, LLM을 이용한 코드 변환의 안정성을 기준으로 언어 간 거리를 정의하는 방식은 매우 현대적이고 독창적인 접근입니다. 이는 언어 간의 '개념적 등가성(Conceptual Equivalence)'을 측정하는 지표가 될 수 있습니다.

이 방법론은 LLM이 두 언어 사이의 개념을 얼마나 정확하게 매핑하는지를 측정하여, 반복적인 변환(Round-trip Translation) 과정에서 발생하는 '정보의 손실률'을 거리로 환산합니다.

1. 측정 메커니즘: Round-trip Iteration
    1) Original ($P_{0}$): C++로 작성된 원본 알고리즘 코드.
    2) Transformation ($T$): LLM을 이용해 C++ → 타 언어(C, Java, Python) → C++ 순으로 교차 변환을 수행.
    3) Iteration ($N$): 이 과정을 $N$번 반복하며 매 단계의 C++ 결과물($P_{n}$)을 저장.
2. 수렴 및 임계치 (Threshold): $P_{n}$과 $P_{n+1}$ 사이의 코드 유사도(CodeBLEU 또는 AST 유사도) 변화량이 특정 임계치(2% 미만) 이하로 떨어지는 지점을 '안정 상태(Fixed Point)'로 정의합니다.
3. 거리 정의 (Distance Metric):
    1) 수렴 속도 ($N$): 안정 상태에 도달하기까지 필요한 반복 횟수가 적을수록 두 언어 사이의 거리는 가깝다고 판단합니다.
    2) 잔차 유사도 ($S$): 최종 수렴된 코드와 원본 코드($P_{0}$) 사이의 유사도 점수가 높을수록 언어적 호환성이 높음을 의미합니다.
