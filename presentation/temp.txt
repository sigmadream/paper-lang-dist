<!-- _header: 5. 후속 방향 (2/4): 구조 지표 정교화 -->

### 누적 변화와 직전 주기의 변화를 따로 계산

$$
\Delta_0(t)=1-s(x_0,x_t), \qquad
\Delta_{\mathrm{step}}(t)=1-s(x_{t-1},x_t)
$$

- $s$: 범위와 방향을 확인한 유사도 함수이며, 지표별 결과를 따로 보고
- $\Delta_0$: 처음 코드에서 얼마나 달라졌는지, $\Delta_{\mathrm{step}}$: 직전 주기에서 얼마나 변했는지 측정
- 도입 순서: 토큰 기준선 → 같은 언어 AST/TSED → 지원 범위를 확인한 PDG/CSSG
- 검증 사례: 식별자 변경, 동치 반복문 변환, 연산자 오류 등 성격이 다른 변형을 비교
- 산출물: 실행 결과와의 관계, 지표별 탐지 실패 사례, 파싱 실패율·계산 비용

> TSED는 AST 편집 기반 유사도이고 CSSG는 의존 관계 기반 지표이며, 둘 다 실행 동치를 보증하지 않는다. [TSED](https://aclanthology.org/2024.acl-short.3/), [CSSG](https://arxiv.org/abs/2601.04085v2).

### "성능이 좋아지면 거리가 수렴한다"는 검증할 가설

- 질문: 같은 경로의 측정값이 모델·프롬프트 변경에도 유지되는가?
- 모델 ID, 크기, 양자화, 컨텍스트 한도, 온도, seed 지원 여부를 기록
- 모델 간 경로 순위의 Spearman 상관과 신뢰구간, 실패 유형의 차이를 보고
- 경로×모델 상호작용이 크면 모델별 행렬을 유지하고 무조건 평균내지 않음
- 모델 규모에 따른 수렴은 같은 계열의 여러 규모와 유사한 학습 조건을 확보한 뒤 별도 검증
- 산출물: 조건 변화에도 유지되는 관측과 모델에 의존하는 관측의 구분

### 알고리즘 문제에서 모듈 단위 이식으로 확대

- 순서: 표준 입출력 문제 → 순수 함수 → 의존성이 제한된 OSS 모듈
- 선정 기준: 라이선스, 빌드 환경, 회귀 테스트, 인터페이스 명세를 확보할 수 있는 코드

| 지표 보완 | 3~4주 | 안정화 확인·누적 변형량·경로 보존 집계 |
| 본 실험 | 5~7주 | 규모 확정 후 조건별 실행과 누락 점검 |
| 분석·집필 | 8~9주 | RQ1~3 결과, 신뢰구간, 실패 사례와 한계 |

- 일정은 인력과 추론 자원 확보를 전제로 한 제안이며 파일럿 후 조정
- 1차 핵심 기여: 성공 안정화 정의, 지표 비교, 모델·프롬프트 민감도
- 다언어 전체 행렬과 OSS 검증은 별도 확장 단계로 진행

<!-- _header: 부록 A. 비교 기준선의 정의와 한계 -->

| 기준선 | 비교 대상과 계산 | 한계 및 주의점 |
| :--- | :--- | :--- |
| 예약어 Jaccard | 언어별 예약어 집합의 교집합/합집합 | 문법·실행 의미를 직접 반영하지 않음 |
| 토큰 Dice | 코드 토큰별 개수의 중복 비율 | 순서를 보지 않으므로 구문 변화에 둔감 |
| AST/TSED | 같은 언어 코드의 AST 편집 기반 유사도 | 파서 버전·노드·편집 비용 고정 필요 |
| 코드 임베딩 | 동일 임베딩 모델의 벡터 간 코사인 유사도 | 학습 분포·입력 길이·모델 버전에 의존 |
| 언어 특성 벡터 | 타입·메모리 관리 등 명시한 속성 비교 | 범주형 속성에 임의 숫자를 부여하지 않음 |

- 코드 단위 유사도를 언어 단위로 집계하려면 문제 분포와 가중치를 명시
- 코사인 유사도의 범위는 일반적으로 $[-1,1]$이므로 다른 지표와 결합하기 전에 척도를 확인
- 기준선은 비교 설계이며, 모두 확립된 언어 거리 측정법이라는 뜻은 아님
