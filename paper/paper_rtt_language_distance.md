## 1. 요약 (Abstract)

본 연구는 대규모 언어 모델(LLM)을 활용한 왕복 번역(Round-Trip Translation, RTT) 기법을 통해 프로그래밍 언어 간 거리를 정량적으로 측정하는 실험적 방법론을 제안한다. 기준 C++ 해법을 C, Java, Python으로 번역한 뒤 다시 C++로 역번역하는 순환 과정을 반복하여, 고정점(fixed point) 도달 여부·반복 횟수·잔차 유사도·AST 구조 거리·MOSS 유사도를 종합적으로 측정하였다. 실험에는 로컬 오픈소스 모델인 Ollama(qwen2.5-coder:7b)와 상용 클라우드 모델인 OpenAI(gpt-5.4)를 각각 사용하였으며, 백준 온라인 저지에서 선별한 5개 알고리즘 문제를 대상으로 총 30건(모델당 15건)의 번역 실험을 수행하였다.

실험 결과, 두 모델은 뚜렷이 상이한 행동 양상을 보였다. Ollama는 전체 15건 중 8건(53.3%)의 완전 성공을 달성하였으며, 특히 cpp→python 변환에서 60%의 의미 보존율(semantic pass rate)로 상대적 강점을 보였다. 반면 OpenAI는 cpp→c 변환에서 100%의 완전 성공률을 기록하였으나, cpp→java 및 cpp→python에서는 전원 실패하여 전체 성공률이 33.3%에 그쳤다. 잔차 유사도 측면에서 Ollama는 성공 사례에서 평균 0.848~0.894의 높은 토큰 보존율을 보인 반면, OpenAI의 cpp→c 성공 사례들은 평균 0.696으로 원본으로부터의 구조적 이탈이 더 컸다. AST 편집 거리 역시 OpenAI가 Ollama 대비 전반적으로 더 큰 값을 기록하여, 상용 모델이 번역 과정에서 코드 구조를 더 크게 재구성하는 경향이 있음을 시사하였다.

이 결과는 LLM 기반 코드 번역의 품질이 모델 규모나 상용 여부보다 언어 쌍의 구문적·의미적 거리 및 모델의 학습 데이터 특성에 더 크게 의존함을 보여준다. 본 연구는 RTT 기반 언어 거리 측정이 LLM의 다국어 코드 이해력을 평가하고, 코드 마이그레이션 난이도를 사전에 추정하는 데 유용한 정량적 프레임워크를 제공할 수 있음을 제안한다.

## 2. 서론 (Introduction)

### 2.1 연구 배경

프로그래밍 언어 간의 "거리"를 정량적으로 측정하려는 시도는 프로그래밍 언어론과 소프트웨어 공학의 오랜 과제이다. 전통적으로 언어 간 유사도는 구문(syntax) 계열, 타입 시스템, 패러다임(절차적·객체지향적·함수형) 등의 정성적 분류에 의존해 왔다. 그러나 이러한 분류는 실제 코드 변환 과정에서 나타나는 구조적·의미적 변형의 정도를 정확히 반영하지 못한다.

한편, 대규모 언어 모델(LLM)의 코드 생성 및 번역 능력이 급속히 발전하면서, LLM을 "번역기"로 활용하여 언어 간 변환을 수행하고 그 과정에서 발생하는 변형을 측정하는 새로운 접근이 가능해졌다. 자연어 처리 분야에서 왕복 번역(round-trip translation)은 기계 번역 품질을 평가하는 고전적 기법이며, 이를 프로그래밍 언어에 적용하면 언어 간 거리를 반영하는 정량적 지표를 도출할 수 있다는 가설이 본 연구의 출발점이다.

### 2.2 연구 목적

본 연구의 목적은 다음 세 가지로 요약된다.

1. RTT 기반 언어 거리 측정 프레임워크 구축: C++를 기준 언어(seed language)로 설정하고, C·Java·Python으로의 왕복 번역 순환을 통해 언어 간 거리를 다차원적으로 측정하는 자동화된 실험 파이프라인을 설계·구현한다.
2. 이종 LLM 간 비교 분석: 로컬 오픈소스 모델(Ollama, qwen2.5-coder:7b)과 상용 클라우드 모델(OpenAI, gpt-5.4)의 번역 행동을 동일 코퍼스·동일 조건에서 비교하여, 모델 특성이 언어 간 거리 측정 결과에 미치는 영향을 분석한다.
3. 다차원 지표의 종합적 해석: 수렴 속도(반복 횟수), 잔차 토큰 유사도, AST 편집 거리, MOSS 표절 검사 유사도, 의미 보존 여부(semantic pass/fail) 등 이질적 지표들의 상호 관계를 분석하여, 각 지표가 드러내는 언어 간 거리의 서로 다른 측면을 조명한다.

### 2.3 논문의 구성

본 논문의 이후 구성은 다음과 같다. 제3장에서는 실험 설계를 상세히 기술하고, 제4장에서는 실험 결과를 표와 함께 해석한다. 제5장에서는 결과에 기반한 제언을, 제6장에서는 결론을 제시한다.

## 3. 실험 설계 (Experimental Design)

### 3.1 실험 코퍼스

실험 대상 코퍼스는 백준 온라인 저지(Baekjoon Online Judge)에서 선별한 5개 알고리즘 문제로 구성된다. 각 문제는 서로 다른 알고리즘 패턴을 포함하도록 선택하였다.

| 문제 ID | 문제명 | 알고리즘 특성 |
| --- | --- | --- |
| IPOP_1436 | 영화감독 숌 | 문자열 탐색, 반복문 |
| IPOP_2110 | 공유기 설치 | 이분 탐색 |
| IPOP_2217 | 로프 | 정렬, 그리디 |
| IPOP_2579 | 계단 오르기 | 동적 프로그래밍 |
| IPOP_5567 | 결혼식 | 정렬, 구간 처리 |

각 문제에는 10쌍의 입출력 샘플 픽스처(fixture)가 제공되어, 번역된 코드의 의미적 정확성(semantic correctness)을 자동으로 검증할 수 있도록 하였다.

### 3.2 기준 언어 및 대상 언어

- 기준 언어(seed language): C++
- 대상 언어(target languages): C, Java, Python
- 언어 쌍(ordered pairs): cpp→c, cpp→java, cpp→python

C++을 기준 언어로 선택한 이유는 (1) 세 대상 언어 모두와 구문적으로 어느 정도 공통 요소를 공유하면서도, (2) 각 언어로의 변환 시 서로 다른 수준의 구조적 변형이 필요하기 때문이다. 특히 C는 C++의 부분 집합에 가까운 구문 유사성을, Java는 객체지향 래핑의 필요성을, Python은 근본적으로 다른 구문 규칙(들여쓰기 기반, 동적 타이핑)을 각각 대표한다.

### 3.3 실험 모델

두 가지 LLM을 사용하여 동일 실험을 독립적으로 수행하였다.

| 항목 | Ollama | OpenAI |
| --- | --- | --- |
| 모델명 | qwen2.5-coder:7b | gpt-5.4 |
| 유형 | 로컬 오픈소스 | 상용 클라우드 API |
| 파라미터 규모 | 7B | 비공개 (대규모) |
| 온도(temperature) | 0 | 0 |
| 실행 환경 | 로컬 머신 | 클라우드 API |
| 실행 ID | smoke-ollama-001 | smoke-openai-001 |

두 모델 모두 temperature를 0으로 고정하여 결정론적(deterministic) 출력을 추구하였다. 다만, temperature=0이더라도 완전한 재현성은 보장되지 않는다는 점에 유의해야 한다.

### 3.4 왕복 번역 파이프라인

실험 파이프라인의 한 주기(cycle)는 다음과 같은 단계로 구성된다.

```
[기준 C++] → (LLM 번역) → [대상 언어 코드] → (컴파일/실행 검증) →
(LLM 역번역) → [왕복 C++ 코드] → (컴파일/실행 검증) → (수렴 판정)
```

수렴 판정(convergence detection)은 다음 규칙에 따른다:

- 고정점(fixed_point): 마지막 두 왕복 C++ 코드의 정규화된 해시가 동일
- 진동(oscillation): 마지막 네 해시가 A, B, A, B 패턴을 보이며 A ≠ B
- 실패 종료(terminated_on_failure): 컴파일 오류, 런타임 오류, 오답, 타임아웃 등으로 중단
- 최대 반복 한도: 20회

### 3.5 측정 지표

각 실험 단위(문제-언어 쌍)에 대해 다음 지표를 수집하였다.

1. 변경 횟수 거리(change-count distance): 완료된 왕복 주기 수. 값이 클수록 수렴에 오래 걸림을 의미한다.
2. 잔차 유사도(residual similarity): 원본 C++와 최종 왕복 C++의 정규화된 토큰 멀티셋 간 Sørensen-Dice 계수. 값이 1에 가까울수록 원본 보존율이 높다.
3. AST 편집 거리(AST distance): tree-sitter로 파싱한 뒤 언어 독립적 IR(중간 표현)로 정규화하고, APTED(All Path Tree Edit Distance) 알고리즘으로 계산한 트리 편집 거리.
4. MOSS 유사도: Stanford MOSS(Measure of Software Similarity) 시스템을 활용한 코드 유사도 측정. seed(원본 C++ 대비)와 roundtrip(왕복 C++ 대비) 두 방향을 기록한다.
5. 의미 보존 여부(semantic pass/fail): 대상 언어 코드와 왕복 C++ 코드가 모든 샘플 입출력을 통과하는지 여부.
6. 복잡도 델타(complexity delta): lizard 도구로 측정한 LOC, token_count, cyclomatic_complexity, function_count, max_nesting_depth의 원본 대비 변화량.

### 4.1 전체 성공률 비교

### 4.2 수렴 속도(반복 횟수) 분석

표 3. 언어 쌍별 평균 반복 횟수 및 변경 횟수 거리

| 언어 쌍 | Ollama 평균 반복 | Ollama 평균 CCD | OpenAI 평균 반복 | OpenAI 평균 CCD |
| --- | ---: | ---: | ---: | ---: |
| cpp→c | 2.2 | 1.8 | 5.4 | 5.4 |
| cpp→java | 2.4 | 2.2 | 1.2 | 0.8 |
| cpp→python | 2.2 | 1.8 | 1.0 | 1.0 |

> CCD: Change-Count Distance (변경 횟수 거리)

주목할 만한 차이가 관찰된다. Ollama는 세 언어 쌍 모두에서 비교적 균일한 수렴 속도(평균 2.2~2.4회)를 보여 언어 쌍에 따른 편차가 작다. 반면 OpenAI는 cpp→c에서 평균 5.4회(IPOP_2217에서 16회 반복)로 매우 느린 수렴을 보이면서도, cpp→java와 cpp→python에서는 대부분 1회차에서 실패로 종료되어 평균값이 낮게 나타났다.

OpenAI의 cpp→c에서 높은 반복 횟수는 역설적으로 해석할 수 있다. 모델이 번역 시 코드 구조를 크게 재구성하면서도 의미적 정확성은 유지하여, 고정점에 도달하기까지 많은 조정이 필요했음을 시사한다.

### 4.3 잔차 유사도 분석

표 4. 성공 사례의 잔차 유사도(Residual Similarity)

| 언어 쌍 | Ollama 평균 | Ollama 표준편차 | OpenAI 평균 | OpenAI 표준편차 |
| --- | ---: | ---: | ---: | ---: |
| cpp→c | 0.848 | 0.015 | 0.696 | 0.118 |
| cpp→java | 0.894 | 0.038 | - | - |
| cpp→python | 0.864 | 0.037 | - | - |

> OpenAI의 cpp→java, cpp→python은 성공 사례가 없어 잔차 유사도 측정 불가

Ollama는 세 언어 쌍 모두에서 0.848~0.894의 높은 잔차 유사도를 보여, 왕복 번역 후에도 원본 C++의 토큰 구조를 상당 부분 보존하는 것으로 나타났다. 또한 표준편차가 0.015~0.038로 작아, 문제의 종류에 관계없이 안정적인 보존율을 유지하였다.

반면 OpenAI의 cpp→c는 평균 0.696으로 Ollama보다 약 15%p 낮으며, 표준편차도 0.118로 문제에 따른 편차가 컸다. 이는 OpenAI가 C 번역 시 원본 C++의 구조를 더 적극적으로 재구성하며, IPOP_5567(0.544)에서 IPOP_2110(0.827)까지 문제 난이도에 따라 재구성 정도가 크게 달라짐을 보여준다.

| IPOP_5567 | cpp→java | 49 | - |

> `*` 진동(oscillation) 상태로 종료된 사례. `-`는 실패하여 측정 불가.

AST 편집 거리에서 가장 두드러진 차이는 cpp→c 변환이다. 두 모델 모두 측정이 가능한 IPOP_2110과 IPOP_2217에서, OpenAI(51, 41)가 Ollama(38, 34)보다 일관되게 더 큰 AST 거리를 보인다. IPOP_5567에서 OpenAI의 AST 거리 125는 Ollama의 60에 비해 2배 이상 크며, 이는 OpenAI가 C 번역 시 함수 분리, 루프 구조 변환 등 대규모 구조적 재구성을 수행하는 경향이 있음을 시사한다.

Ollama의 cpp→java 변환은 AST 거리가 12~49로 넓은 범위를 보이며, 이는 Java의 클래스 래핑 등 필수적 구조 변환의 정도가 문제 복잡도에 따라 달라짐을 반영한다.

> `-`는 미측정 또는 실패. 0%는 MOSS가 유의미한 공통 구간을 발견하지 못한 경우.

MOSS 유사도는 잔차 유사도와 다른 관점을 제공한다. 잔차 유사도가 토큰 수준의 겹침을 측정하는 반면, MOSS는 최소 매칭 단위(보통 수 줄 이상)의 구조적 유사 구간을 탐지한다. 예를 들어, Ollama의 IPOP_1436/java는 잔차 유사도 0.873으로 높지만 MOSS seed 유사도는 64%로, 토큰은 상당수 보존되었으나 코드 구조(줄 순서, 블록 구성)는 일부 변형되었음을 보여준다.

흥미로운 점은 IPOP_5567에서 OpenAI의 roundtrip MOSS가 90%인 반면 seed MOSS가 29%인 경우이다. 이는 번역 과정에서 구조적 재구성이 일어났으나, 역번역 시 해당 재구성이 상당 부분 복원되어 왕복 C++ 코드가 원본과는 다르지만 일관된 구조를 유지했음을 시사한다.

표 7. 수렴 결과 유형별 분포

| 수렴 유형 | Ollama 건수 | OpenAI 건수 |
| --- | ---: | ---: |
| fixed_point | 8 | 5 |
| oscillation | 2 | 0 |
| terminated_on_failure | 5 | 10 |
| 합계 | 15 | 15 |

Ollama에서 관찰된 2건의 진동(oscillation)은 주목할 만하다. IPOP_2110/java(4회 반복)와 IPOP_5567/c(5회 반복)에서 발생한 진동은 번역이 A→B→A→B 패턴으로 순환하면서도 의미적 정확성은 유지하는 상태로, 이는 해당 언어 쌍에서 동등한 두 가지 표현이 안정적으로 공존할 수 있음을 시사한다.

OpenAI의 실패 10건 중 compile_error가 8건, parse_error가 2건으로, 대부분 역번역된 C++ 코드의 컴파일 오류가 원인이었다. 이는 OpenAI가 대상 언어로의 순방향 번역은 성공하더라도, 역방향 번역 시 C++ 구문 규칙을 정확히 준수하지 못하는 경향이 있음을 보여준다.

반면 Ollama의 cpp→python 변환은 전반적으로 LOC와 token_count가 줄어드는 경향을 보여, Python의 간결한 구문이 코드 압축 효과로 이어지는 자연스러운 패턴이 관찰된다.

## 5. 제언 (Recommendations)

### 5.1 실험 설계 개선을 위한 제언

#### 5.1.1 코퍼스 확장의 필요성

현재 5개 문제로 구성된 실험 코퍼스는 예비 연구(pilot study)로서는 충분하나, 통계적으로 유의미한 결론을 도출하기에는 표본 크기가 제한적이다. 다음과 같은 확장을 제안한다.

- 문제 수 확대: 최소 20~30개 문제로 확장하여 알고리즘 유형별 충분한 대표성을 확보
- 난이도 스펙트럼 확장: 현재 코퍼스에 없는 그래프 알고리즘, 트리 탐색, 문자열 처리 심화 문제 추가
- 코드 복잡도 다양화: 단일 함수 해법뿐 아니라 복수 함수·클래스 구조를 포함하는 해법 추가

#### 5.1.2 대상 언어 확장

현재 C, Java, Python의 세 언어에 더해, 다음 언어의 추가를 고려할 수 있다.

- Rust: 소유권(ownership) 개념으로 인한 높은 변환 난이도
- Go: 간결한 구문이지만 제네릭 부재(Go 1.18 이전)로 인한 독특한 변환 패턴
- JavaScript/TypeScript: 동적·정적 타이핑의 경계에서의 번역 행동

#### 5.1.3 멀티 시드 실험

C++ 이외의 언어를 기준으로 한 양방향 측정을 통해 언어 거리의 비대칭성(asymmetry)을 검증할 필요가 있다. 예를 들어, Python→C++ 거리와 C++→Python 거리가 동일한지 비교하면, LLM이 특정 방향의 번역에 체계적 편향을 가지는지 확인할 수 있다.

### 5.2 모델 활용을 위한 제언

#### 5.2.1 언어 쌍별 최적 모델 선택

실험 결과는 "만능 번역 모델"이 존재하지 않는다는 점을 시사한다. 실무적으로는 다음과 같은 언어 쌍별 전략을 고려할 수 있다.

- cpp→c 변환: OpenAI(gpt-5.4)가 100% 성공률로 더 적합하지만, 코드 구조가 크게 변형될 수 있으므로 구조 보존이 중요하다면 Ollama 검토
- cpp→java 변환: Ollama(qwen2.5-coder:7b)가 60~80% 성공률로 현재 유일한 실용적 선택지
- cpp→python 변환: Ollama가 60% 성공률로 상대적 우위이나, 런타임 에러 위험이 존재

#### 5.2.2 실패 패턴에 대한 대응 전략

OpenAI의 주된 실패 원인인 compile_error/parse_error에 대해 다음 전략을 제안한다.

- 컴파일 오류 자동 수정 루프: 역번역된 C++의 컴파일 오류를 LLM에 피드백하여 수정을 시도하는 반복 구조 추가
- 구문 검증 사전 필터링: 역번역 결과를 AST 파싱하여 기본적인 구문 유효성을 확인하고, 실패 시 재번역 요청
- 다중 모델 앙상블: 한 모델의 실패 시 다른 모델로 폴백하는 전략

### 5.3 지표 체계 개선을 위한 제언

#### 5.3.1 가중 복합 지표 도입

현재 개별적으로 보고되는 지표들을 가중 결합하여 단일 "언어 거리 점수"를 산출하는 방안을 고려할 수 있다.

```
D(L₁, L₂) = α · (1 - residual_similarity) + β · normalized_AST_distance + γ · log(iterations)
```

여기서 α, β, γ는 연구 목적에 따라 조정 가능한 가중치이며, AST 거리는 코퍼스 내 최대값으로 정규화한다.

#### 5.3.2 의미적 등가성의 세분화

현재의 이진(pass/fail) 의미 보존 판정을 세분화하여, 부분 통과율(예: 10개 중 7개 통과), 출력 차이의 정도(수치 오차, 형식 차이 등)를 기록하면 의미적 측면에서의 언어 거리를 더 세밀하게 측정할 수 있다.

## 6. 결론 (Conclusion)

### 6.1 주요 발견

본 연구는 LLM 기반 왕복 번역을 활용하여 프로그래밍 언어 간 거리를 정량적으로 측정하는 실험적 방법론을 제안하고, Ollama(qwen2.5-coder:7b)와 OpenAI(gpt-5.4) 두 모델에 대한 비교 실험을 수행하였다. 주요 발견은 다음과 같다.

1. 모델 특성과 언어 쌍의 상호 작용: 두 모델은 언어 쌍에 따라 상반된 강점을 보였다. OpenAI는 cpp→c에서 100% 성공하였으나 cpp→java/python에서는 전원 실패하였고, Ollama는 세 언어 쌍 모두에서 균형 잡힌 성공률(40~60%)을 유지하였다. 이는 모델 규모와 번역 품질의 단순 비례 관계가 성립하지 않음을 보여준다.

2. 구조 보존과 의미 보존의 트레이드오프: OpenAI는 의미적 정확성을 달성하면서도 코드 구조를 크게 재구성하는 경향이 있어(낮은 잔차 유사도, 높은 AST 거리), "성공"의 질적 측면에서 Ollama와 차이를 보였다. Ollama는 상대적으로 원본에 가까운 구조를 유지하면서 번역하는 보수적 전략을 취했다.

3. 언어 간 거리의 다차원성: 잔차 유사도, AST 거리, MOSS 유사도, 수렴 속도는 언어 간 거리의 서로 다른 측면을 포착하였으며, 이들은 반드시 일치하지 않았다. 예를 들어, cpp→python은 높은 잔차 유사도를 보이면서도 MOSS 유사도가 0%인 경우가 빈번하여, 토큰 수준의 보존과 구조 수준의 보존이 독립적일 수 있음을 확인하였다.

4. 진동의 발견: Ollama에서 관찰된 2건의 진동(oscillation)은 특정 언어 쌍에서 동등한 두 가지 코드 표현이 안정적으로 교대할 수 있음을 보여주며, 이는 언어 간 번역에서 "정답"이 유일하지 않다는 점을 정량적으로 입증하였다.

### 6.2 방법론적 기여

본 연구의 방법론적 기여는 다음과 같다.

- 자동화된 RTT 파이프라인: 코드 번역, 컴파일, 실행 검증, 수렴 판정, 다차원 지표 측정을 완전히 자동화한 실험 프레임워크를 구현하였다.
- 다차원 거리 지표: 단일 지표에 의존하지 않고, 토큰(잔차 유사도)·구조(AST 거리)·표절 검사(MOSS)·의미(semantic pass/fail)·복잡도(lizard 메트릭) 다섯 축을 동시에 측정하여 언어 간 거리의 복합적 특성을 포착하였다.
- 이종 모델 비교 프로토콜: 동일 코퍼스·동일 조건 하에서 이종 LLM의 번역 행동을 체계적으로 비교할 수 있는 실험 프로토콜을 확립하였다.

### 6.3 한계 및 향후 연구

본 연구의 주요 한계와 이에 따른 향후 연구 방향은 다음과 같다.

- 표본 크기: 5개 문제×3개 언어 쌍은 통계적 검정력이 제한적이다. 표본을 최소 20~30개 문제로 확장해야 언어 쌍별 차이의 통계적 유의성을 검증할 수 있다.
- 단방향 측정: C++를 유일한 기준 언어로 사용하여 언어 거리의 비대칭성을 확인할 수 없었다. 양방향 RTT 실험을 통해 D(A→B) ≠ D(B→A)인지 검증할 필요가 있다.
- 모델 다양성: 두 모델만 비교하였으므로, Claude, Gemini, CodeLlama 등 다양한 모델로의 확장을 통해 "모델 불변적(model-invariant)" 언어 거리 측정의 가능성을 탐색해야 한다.
- 재현성 한계: temperature=0에서도 LLM 출력의 완전한 결정론성이 보장되지 않으며, 모델 버전 업데이트에 따라 결과가 변할 수 있다.

이러한 한계에도 불구하고, 본 연구는 LLM 기반 왕복 번역이 프로그래밍 언어 간 거리를 정량적으로 측정하는 유망한 방법론임을 보여주었으며, 이 접근법이 코드 마이그레이션 계획 수립, LLM 번역 능력 벤치마킹, 프로그래밍 언어 계통학(phylogenetics) 연구 등에 활용될 수 있음을 제안한다.
