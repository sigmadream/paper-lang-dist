# 공통 문제와 초기 구현 차이

15문제는 번역 전에 5영역에서 각 3개씩 선정했다. 문제별 명세, 공개 예제, C++ 기준 구현, 평가 입력 13쌍은 기존 `problem/`에서 수정 없이 복사했다. Haskell과 Prolog는 별도로 구현했다. 모든 출발 언어에 같은 입력·정답·제한 시간을 적용했다. 세 구현의 585개 검사 성공과 파일 해시는 `artifacts-lmstudio/fps-v1/preflight-authorized/validation.json`에 있다. 선정·제외 목록은 `data/fps-v1/selection.json`이다.

모든 프로그램은 stdin을 읽고 stdout에 명세의 결과만 출력한다. C++는 스트림 입력과 가변 자료 구조, Haskell은 getContents 및 words 기반 입력과 불변 값, Prolog는 read_string/split_string과 술어 호출을 주로 사용한다. Prolog는 평가기가 main/0을 호출한다. 중복 해나 탐색 순서에 의존하는 출력은 허용하지 않으며 결과 정수·리스트의 순서를 각 명세로 고정한다. 정렬 문제는 내장 정렬을 금지하고, 다른 문제의 표준 정렬·집합 라이브러리는 허용한다.

정수·문자열·배열의 범위는 문제별 statement.md를 따르며 축소하지 않았다. 예를 들어 소수 상한은 10^6, 중복 배열은 10^5, 정렬은 5×10^4, 그래프 연결 성분은 정점 200, 친구 관계는 정점 500·간선 10,000이다. C++의 고정 폭 정수와 Haskell/Prolog 정수 표현의 차이는 있으나 명세의 결과 범위와 경계 평가를 모두 통과했다. 검사는 컴파일 90초, 입력당 30초로 고정했다. 기존 13개 입력에는 작은 값·반복값·순서 변형·규모 경계 등이 포함되며, 명세가 빈 입력을 허용하지 않아 빈 입력은 추가하지 않았다.

단순 팰린드롬·최대공약수도 실제 판정 로직이 있으나 짧은 기준 코드와 공통 래퍼의 영향이 클 수 있다. 특히 C++의 LC 공통 입출력 함수에는 문제에 따라 사용하지 않는 함수도 포함된다. 기준 구현을 번역 결과에 맞춰 삭제·축소하지 않았고, 이 표와 유사도 진단에서 그 영향을 공개한다. 따라서 측정 차이는 언어만의 효과가 아니라 알고리즘·자료 표현·래퍼 선택과 결합된 효과다. 유한 평가 통과는 전체 명세의 형식적 증명이 아니다.
